# Learn How to Build Multi-Agent Systems With Swarms Cloud: Two New Video Tutorials

Two new video tutorials are now live, covering two of the most powerful features on Swarms Cloud: the Auto Agent Builder and the Compare feature. Both are taught by our Co-Founder and CEO Kye Gomez, and both walk through real workflows on the platform from start to finish.

The tutorials cover how to:

- Generate complete AI agent teams from a natural language description with the Auto Agent Builder
- Run the same task through multiple agents simultaneously and evaluate their outputs side by side with Compare
- Get more out of the latest Swarms Cloud features

More tutorials are on the way, and a complete Swarms Cloud course is in production to take you from the fundamentals to building advanced agent workflows.

## Tutorial 1: Generate AI Agent Teams With Natural Language Using the Auto Agent Builder

The first tutorial introduces the Auto Agent Builder on Swarms Cloud. You describe a task in plain language, and the builder automatically designs a complete agent team: specialized roles, system prompts, model selection, and generation parameters, all configured in seconds.

The video walks through the feature end to end, from writing the initial task description to reviewing and editing the generated agents. If you have been building agent teams by hand, writing each system prompt and picking each model yourself, this tutorial shows how much of that work the builder now does for you.

[Watch on YouTube](https://www.youtube.com/@kyegomez3242)

For a full written introduction to the feature, read the [Auto Agent Builder announcement](/blog/introducing-auto-agent-builder).

## Tutorial 2: Compare AI Agents Side by Side

The second tutorial showcases the Compare feature on Swarms Cloud. Compare lets you run the same task through multiple AI agents simultaneously and view their responses side by side.

This solves a problem every agent developer runs into: two agents with different models, prompts, or parameters will produce different outputs, and the only honest way to pick between them is to test them on the same input. Compare turns that evaluation into a single step. Run the task once, read the outputs next to each other, and keep the configuration that performs best.
