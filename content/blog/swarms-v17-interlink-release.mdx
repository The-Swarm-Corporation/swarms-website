# Swarms v17 "InterLink"

InterLink is one month of work: **227 commits between October 2 and November 2, 2026**, across 271 files, **+15,729 / −13,395 lines**. For the first time in a major release, `swarms/` itself got smaller: **+5,845 / −8,080**, a net 2,235 lines removed while eleven new modules landed. `tests/` grew by +8,378 / −960, and the suite went from 944 test functions to 1,130.

Zena (v14) made the framework observable. Akira (v15) made it honest. Overclock (v16) made it measurable and fast. InterLink makes it **connected and lean**.

Five threads run through this release.

The first is **channels**, which is where the name comes from. An agent's conversation used to live in its own memory and nowhere else. Now any `Agent`, and nine structures, can take a `channel=`: a place they read what was said before a run and post what they say after it. Six channels ship. A Markdown file you can open while the agents talk, a queue a consumer thread blocks on, a SQLite table safe across processes, a remote HTTP server, an email thread in your own inbox, and an AgentMail thread that people can reply to from their mail client. A second run on a non-empty channel continues where the first left off.

The second is **start-up speed**. `import swarms` took **1.91 seconds**; it now takes **0.28** (median of nine fresh processes on the same machine, v16 against v17). It no longer loads litellm, RouteHub, mcp, networkx, OpenTelemetry, starlette or sqlite3 until something uses them, it writes nothing to disk, and building an `Agent` whose limits are set opens no network connection. Installing `swarms[fast]` routes model calls through RouteHub, which cuts per-call overhead by more than half and peak memory from about 220 MB to 100 MB.

The third is **full-width concurrency**. `ConcurrentWorkflow` ran at most 32 agents at once and `GraphWorkflow` sized its pool to CPU cores, so a 100-node layer on a 12-core laptop ran in waves of 11. Both now run every node at once by default: a 100-node fan-out goes from **2.04 s to 0.21 s**, against 1.44 s for LangGraph on the same graph.

The fourth is **answers, not transcripts**. `Agent.run` returns the whole conversation under its default `output_type`, and seven structures and helpers used that value as if it were the agent's reply. `HeavySwarm` returned a 382,000-character transcript where it meant a 24-character answer. `ReflexionAgent` nested every iteration inside the next. `handoff_task`, `GKPAgent`, `ExpertPanelDiscussion` and `IterativeReflectiveExpansion` had the same bug. Each now records and returns the answer.

The fifth is **failures that raise, and a smaller surface**. `HeavySwarm`, `MixtureOfAgents`, `MajorityVoting`, `AuctionSwarm` and `AgentRearrange` returned an error string, or cast an exception as a vote, so `SwarmRouter(fallback_swarms=...)` never fell back. They now raise. Retries and fallbacks collapse from three stacked layers into one flat loop. And more than forty parameters, methods, modules and classes that did nothing, or did the wrong thing, are gone: `SwarmRearrange`, `create_agents_from_yaml`, half of `BaseTool`, `multi_modal`, `sop`, `n`, `bulk_run` and the rest.

This post covers all of it. New features and improvements first, then a **day-by-day, commit-by-commit** record of the entire release.

**If you are coming from v16, read [Breaking Changes](#breaking-changes) first.** `Agent()` now sends no system prompt unless you give it one, workflows no longer autosave by default, failed swarms raise instead of returning an error string, and a long list of unused parameters is gone. ## New Features

### Comms channels: agents that read and post through a shared medium

**The headline capability of InterLink.** A `CommsChannel` is a place agents read what others said and post what they say. The interface is two methods and one optional one:

```python
class CommsChannel(ABC):
    def post(self, agent_name: str, content: str) -> None: ...  # append one message
    def messages(self) -> List[Dict[str, Any]]: ...            # [{"agent_name": ..., "content": ...}], oldest first
    def clear(self) -> None: ...                               # optional
```

Six implementations ship, all exported from `swarms`:

| Channel | Where the conversation lives | Good for | PR |
|---|---|---|---|
| `FileChannel(path)` | A `.md` or `.txt` file, one `## @name` header per message | Watching agents talk live, editing the transcript between runs | [#2826](https://github.com/kyegomez/swarms/pull/2826) |
| `QueueChannel(q=None)` | In-process history plus a queue | A consumer thread that blocks on each message as it lands; pass a `multiprocessing.Queue` to cross processes | [#2826](https://github.com/kyegomez/swarms/pull/2826) |
| `SqliteChannel(path, name)` | Rows in a SQLite table, many conversations per file | Thread- and process-safe shared state, SQL over the history | [#2826](https://github.com/kyegomez/swarms/pull/2826) |
| `HttpChannel(url, headers)` | Another server, over `GET` / `POST` / `DELETE` | Agents on different machines sharing one conversation | [#2908](https://github.com/kyegomez/swarms/pull/2908) |
| `SmtpChannel(...)` | An email thread in your own inbox, over SMTP and IMAP | People replying to agents from their mail client | [#3036](https://github.com/kyegomez/swarms/pull/3036) |
| `AgentMailChannel(inbox_id, to)` | An email thread in an AgentMail inbox, over its REST API | The same, without running a mail server | [#3034](https://github.com/kyegomez/swarms/pull/3034) |

Give one to an agent and it reads the channel as prior turns before it runs, posts the task once, and posts its final answer under its `agent_name` after a successful run. A failed run posts nothing.

```python
from swarms import Agent, FileChannel

channel = FileChannel("runs/ev_conversation.md")

researcher = Agent(
    agent_name="Researcher",
    system_prompt="You gather facts and figures. Answer in a short bullet list.",
    model_name="gpt-5.4",
    max_loops=1,
    channel=channel,
)
writer = Agent(
    agent_name="Writer",
    system_prompt="You turn the facts in the conversation into a short report.",
    model_name="gpt-5.4",
    max_loops=1,
    channel=channel,
)

task = "Report on the EV battery market."
researcher.run(task)
writer.run(task)   # the writer reads the researcher's answer as a prior turn

print(channel.path.read_text())
```

The file is plain Markdown, so you can open it in an editor while the run is going:

```markdown
## @Human

Report on the EV battery market.

## @Researcher

- Global demand grew 31% last year ...

## @Writer

The EV battery market ...
```

**Structures take a channel too.** `SequentialWorkflow`, `AgentRearrange`, `ConcurrentWorkflow`, `GraphWorkflow`, `MixtureOfAgents`, `GroupChat`, `HierarchicalSwarm`, `PlannerWorkerSwarm` and `MajorityVoting` accept `channel=` and hand it to the `Conversation` they build, including the ones they rebuild for every task. `SwarmRouter` forwards it to whichever swarm it builds. A structure detaches its members' own channels, with a warning, so the transcript is written exactly once, and a fan-out posts its answers in agent order rather than interleaved.

```python
from swarms import Agent, FileChannel, SequentialWorkflow

workflow = SequentialWorkflow(
    agents=[researcher, writer, reviewer],
    max_loops=1,
    channel=FileChannel("runs/sequential.md"),
)
workflow.run("Report on the EV battery market.")
```

**A non-empty channel continues the run.** This is the feature that makes a file channel more than a log. Edit `runs/sequential.md` by hand, then point a new structure at it:

```python
editor = Agent(
    agent_name="Editor",
    system_prompt="Tighten the report in the conversation to half its length.",
    model_name="gpt-5.4",
    max_loops=1,
)

SequentialWorkflow(
    agents=[editor], max_loops=1, channel=FileChannel("runs/sequential.md")
).run("Shorten the report above.")
```

`GroupChat`, `HierarchicalSwarm` and `PlannerWorkerSwarm` initially cleared their conversation at the start of each run, which threw that seed away. They now rebuild it from the channel instead ([#2880](https://github.com/kyegomez/swarms/pull/2880)).

**Stream every message as it lands** with a `QueueChannel`. The consumer blocks on `wait()` or iterates, and `close()` ends the loop:

```python
import threading
from swarms import QueueChannel, SequentialWorkflow

channel = QueueChannel()
workflow = SequentialWorkflow(agents=[researcher, analyst, writer], channel=channel)

def produce():
    try:
        workflow.run("Report on the EV battery market.")
    finally:
        channel.close()

threading.Thread(target=produce, daemon=True).start()

for message in channel:   # blocks until the next post
    print(f"\n[{message['agent_name']}]\n{message['content']}")
```

**Keep many conversations in one database** with a `SqliteChannel`. It is safe for threads and processes (the PR posts 40 messages from 8 threads concurrently), and `fetch_messages()` returns rows with ids and timestamps:

```python
from swarms import SqliteChannel

channel = SqliteChannel("runs/channels.db", name="ev-batteries")
SequentialWorkflow(agents=[researcher, analyst, writer], channel=channel).run(
    "Report on the EV battery market."
)

for row in channel.fetch_messages():
    print(row["created_at"], row["agent_name"], row["content"][:80])

SqliteChannel.list_conversations("runs/channels.db")   # ['ev-batteries', ...]
```

**Share a conversation across machines** with an `HttpChannel`. The URL names one conversation, and the server answers three calls on it. It uses `httpx`, which is already a dependency, and a standard-library reference server ships in `examples/channel_examples/http_channel_server.py`:

| Call | Server does | Body |
|---|---|---|
| `GET url` | Return every message, oldest first | `[{"agent_name": ..., "content": ...}, ...]` |
| `POST url` | Append one message | `{"agent_name": ..., "content": ...}` |
| `DELETE url` | Remove every message | none |

```python
from swarms import Agent, HttpChannel

channel = HttpChannel(
    "https://your-server/channels/ev-report",
    headers={"Authorization": "Bearer ..."},
)
Agent(agent_name="Researcher", model_name="gpt-5.4", channel=channel).run("Report on EVs.")
```

**Put people in the loop by email.** `SmtpChannel` threads every post into one email conversation in your own mailbox, and a person's reply from Gmail or Outlook comes back as a turn, with the quoted history stripped. It uses only the standard library and reads `SMTP_USERNAME` and `SMTP_PASSWORD` from the environment.

```python
from swarms import Agent, SmtpChannel

channel = SmtpChannel(
    from_address="agents@yourco.com",
    to="you@yourco.com",
    smtp_host="smtp.yourco.com",
    imap_host="imap.yourco.com",
    subject="EV battery market report",
)

Agent(agent_name="Researcher", model_name="gpt-5.4", channel=channel).run(
    "Report on the EV battery market."
)
```

A few details in the implementation earn their place. Bodies are sent as base64 of the exact bytes, because `Agent.run` finds its task by exact text and `set_content` otherwise adds a newline. An instance merges its own posts by `Message-ID`, so it does not depend on the Bcc copy arriving before the next agent reads. Quote stripping applies only to human replies, so a `>` blockquote inside an agent's answer survives. And `clear()` requires the server's UIDPLUS extension, because a plain `EXPUNGE` would also remove unrelated mail already flagged for deletion. Microsoft 365 is documented as unsupported, because Exchange Online no longer accepts passwords over IMAP.

`AgentMailChannel` does the same through [AgentMail](https://agentmail.to)'s API, with `AGENTMAIL_API_KEY`. It was built against the live API, and the PR records what that changed. An agent's own posts are read back by an `X-Swarms-Length` header rather than AgentMail's extracted text, which kept a free-plan footer and cut posts at lines such as `Sent from my iPhone`. And the agent headers are believed only on mail labelled `sent`, so a reply with a forged `X-Swarms-Agent` cannot put words in an agent's mouth.

```python
from swarms import AgentMailChannel

channel = AgentMailChannel(
    inbox_id="research@agentmail.to",
    to="you@example.com",
    subject="EV battery market report",
)
```

**Write your own.** Anything with `post` and `messages` is a channel: a Redis list, a Slack thread, a database you already run.

```python
from swarms import Agent, CommsChannel

class ListChannel(CommsChannel):
    def __init__(self):
        self.rows = []

    def post(self, agent_name: str, content: str) -> None:
        self.rows.append({"agent_name": agent_name, "content": content})

    def messages(self):
        return list(self.rows)

    def clear(self) -> None:
        self.rows.clear()
```

Channel rows carry an `agent_name`, not a chat role. The conversion to `user` and `assistant` turns happens in exactly two places, `Agent.run` and `Conversation`, so nothing else in the package ever sees a channel row. Eighteen runnable scripts, one per structure plus the queue, SQLite, HTTP, email and resume cases, are in `examples/channel_examples/`.

### `PhasedFanOutWorkflow`: a lead agent plans a run across many fresh agents

A new structure for tasks whose width you only know at run time: "find every bug in these files, then verify each one", or "read every contract, then have every candidate clause checked independently" ([#2599](https://github.com/kyegomez/swarms/pull/2599)).

```python
from swarms.structs.phased_fan_out_workflow import PhasedFanOutWorkflow

workflow = PhasedFanOutWorkflow(model_name="gpt-5.4", worker_model_name="gpt-5.4-mini")
print(workflow.run("Find every bug in these files and verify each one: ..."))

workflow.last_plan   # the WorkflowPlan the lead wrote
workflow.last_run    # outputs per step, failures, agent count
workflow.usage       # provider tokens over the lead and every worker
```

It works in four stages:

1. **Plan.** The lead returns a `WorkflowPlan` as JSON: inline agents, phases of steps, and the steps whose outputs it wants back. The plan is data, not code, so nothing the model writes is executed.
2. **Validate.** Unknown agents, references to steps that are not in an earlier phase, `{item}` outside a fan-out, a `for_each` on a field the source step's `output_schema` does not declare as an array, and the static agent count are all checked before anything runs. Two checks came out of live testing. A step with no `{task}`, `{item}` or `{step_id}` placeholder is rejected, because its agent would see none of the material. Two steps in one phase with the same agent and prompt are rejected too, because they would do the same work. A rejected plan goes back to the lead with its errors, up to `max_plan_attempts`.
3. **Execute.** Phases run in order and the steps in a phase run in parallel, bounded by `max_concurrent_agents`. A `for_each` step runs one fresh agent per item of a list an earlier step returned. A fan-out that would pass `max_agents` stops before any of its agents start. A failed fan-out slot becomes `None` and is listed in `last_run["failures"]`; a failed single step raises `PhasedFanOutWorkflowError`.
4. **Combine.** The lead reads only the requested outputs and writes the answer.

Predefined agents are rebuilt from their constructor arguments for every use, because `copy.deepcopy(Agent)` raises, so no conversation state carries between steps or runs. Pass your own with `agents=[...]` and `allow_inline_agents=False` to restrict the lead to them:

```python
from swarms import Agent
from swarms.structs.phased_fan_out_workflow import PhasedFanOutWorkflow

reader = Agent(
    agent_name="Clause-Reader",
    agent_description="Reads one contract and quotes any change-of-control clause.",
    system_prompt="You read a single contract and quote, word for word, every clause triggered by a change of control. If there is none, say so.",
    model_name="gpt-5.4-mini",
    max_loops=1,
)
checker = Agent(
    agent_name="Clause-Checker",
    agent_description="Independently checks whether a quoted clause really is a change-of-control clause.",
    system_prompt="You are a skeptical contracts lawyer. Decide whether the quoted clause is triggered by a change of control.",
    model_name="gpt-5.4-mini",
    max_loops=1,
)

workflow = PhasedFanOutWorkflow(
    model_name="gpt-5.4",
    agents=[reader, checker],
    allow_inline_agents=False,
    size_guideline="small",
)
print(workflow.run(task_with_four_contracts))
```

On real models, the bug-hunt example found and confirmed all three planted bugs in about 14,000 tokens, and the contract review found and quoted both change-of-control clauses on three of three runs. A follow-up fix lets the lead's JSON be followed by a closing line of prose, which had cost a plan attempt or failed a worker step with `Extra data` ([#2611](https://github.com/kyegomez/swarms/pull/2611)). Both examples are in `examples/multi_agent/phased_fan_out_workflow/`.

### `swarms[fast]`: RouteHub for model calls, rustworkx for graphs

`pip install "swarms[fast]"` installs [RouteHub](https://github.com/The-Swarm-Corporation/RouteHub), and swarms makes every model call through it instead of litellm ([#2527](https://github.com/kyegomez/swarms/pull/2527)). No code changes. A plain `pip install swarms` keeps litellm and behaves as before, and `SWARMS_LLM_BACKEND=litellm` forces litellm while RouteHub is installed.

```bash
pip install -U "swarms[fast]"

# force litellm even with RouteHub installed
export SWARMS_LLM_BACKEND=litellm
```

Every litellm import in the package now goes through one module, `swarms/utils/llm_backend.py`, and the chosen library is imported on the first model call rather than at `import swarms`. Measured in the PR against a local OpenAI-compatible server, so the numbers isolate swarms and the client library:

| | v16 | v17, litellm | v17, RouteHub |
|---|---|---|---|
| Total import, backend included | 1,050 ms | 1,040 ms | 410 ms |
| Cold start to first answer | ~1,210 ms | ~1,140 ms | ~580 ms |
| Peak RSS | ~220 MB | ~210 MB | ~100 MB |
| One LLM call (`LiteLLM.run`) | 1.5 ms | 1.7 ms | 0.67 ms |
| Streaming run | ~4.8 ms | ~5.3 ms | ~1.2 ms |

With RouteHub, `set_verbose`, `ssl_verify`, `num_retries` and `drop_params` are sent with each call instead of being module globals, so agents no longer overwrite each other's settings. `swarms[fast]` requires RouteHub 0.2.0 or newer ([#2529](https://github.com/kyegomez/swarms/pull/2529)), the first release that stops sending `temperature`, `top_p` and `top_k` to Claude models that reject them. Two things work differently on RouteHub: model details come from OpenRouter's catalog (fetched once and cached for five minutes), and local servers need `/v1` in `llm_base_url`, for example `http://localhost:11434/v1` for Ollama.

The same extra now installs [rustworkx](https://github.com/Qiskit/rustworkx), the Rust graph library behind `GraphWorkflow(backend="rustworkx")` ([#2595](https://github.com/kyegomez/swarms/pull/2595)). The default backend stays networkx, and since [#2590](https://github.com/kyegomez/swarms/pull/2590) none of networkx, rustworkx or graphviz loads until a graph is built.

### `DecisionModel`: OpenAI's gpt-6-luna, prices, and cost per request

v16 introduced `DecisionModel` for typed, calibrated decisions from TypeSafe's Jev and Cloudflare's Clef. InterLink adds a third provider and makes every call priceable.

**OpenAI's Decisions API** ([#2494](https://github.com/kyegomez/swarms/pull/2494)). `DecisionModel(model_name="gpt-6-luna")` calls `https://api.openai.com/v1/decisions` with `OPENAI_API_KEY`. Questions go in and answers come back in the same shape as for the other two providers, so switching provider is a model-name change:

```python
from swarms import DecisionModel

model = DecisionModel(model_name="gpt-6-luna")

result = model.run(
    state="Export fails in Safari but works in Chrome. I was charged twice for my order.",
    questions={
        "department": {
            "type": "choice",
            "instructions": "Which department should handle this complaint?",
            "criteria": {
                "billing": "Payments, invoices, and refunds.",
                "technical": "Problems using the product.",
                "shipping": "Delivery and tracking.",
            },
        },
        "severity": {
            "type": "score",
            "instructions": "How severe is this issue?",
            "criteria": [
                "Cosmetic: appearance only, no lost functionality.",
                "Workaround available: a task fails, but another way works.",
                "Fully blocked: a task fails with no workaround.",
            ],
        },
        "is_urgent": {"type": "noul", "instructions": "The customer needs a reply today."},
    },
)
```

Under the hood a `noul` becomes an OpenAI `predicate`, choice criteria become `choices` and score criteria become `levels`, and the answers are keyed back by question id. A dict or list state is sent as JSON, and a list of `user` messages passes through, so `input_image` parts work. The provider calls the HTTP API with `httpx`, so there is no `openai` dependency. A refusal raises `RuntimeError`, keeping the rule that every question gets an answer of its own type. The live example returned `billing` at confidence 0.88 for 1,517 input tokens, which cost $0.000152.

**Prices and summed usage** ([#2431](https://github.com/kyegomez/swarms/pull/2431)):

```python
from swarms import DecisionModel, get_decision_model_prices

get_decision_model_prices()
# {"jev-latest": {"input": 0.042, "output": 0.0}, ..., "clef": {"input": 0.24, ...}, "gpt-6-luna": {"input": 0.10, "output": 0.0}}

model = DecisionModel()
response = model.run(state, questions)

model.usage                            # summed over every request, including choice(), score() and noul()
model.calculate_cost(response["usage"])  # this request
model.calculate_cost()                   # every request so far
# {"input_tokens": 310, "output_tokens": 47, "input_cost": 1.302e-05, "output_cost": 0.0, "total_cost": 1.302e-05}
```

Prices are US dollars per million tokens. TypeSafe publishes none, so the Jev models use a built-in $0.042 input price with free output, as TypeSafe's own `Usage` schema describes. Clef prices are read live from Cloudflare's model search when credentials are set, with built-in fallbacks. `examples/decision_models/simple_openai.py` is the minimal version ([#2495](https://github.com/kyegomez/swarms/pull/2495)).

### The whole autonomous run streams

With streaming on, `LLMManager` forwarded only `delta.content`. In `max_loops="auto"` almost every turn is a tool call (`create_plan`, your tools, `subtask_done`, `complete_task`), so a streaming consumer saw anywhere from nothing to a sentence of narration, and the final answer, which lives inside `complete_task`'s arguments, never streamed at all. Thinking was held back and printed afterwards ([#2636](https://github.com/kyegomez/swarms/pull/2636)).

`LLMManager.stream_parts` now yields everything the model streams as it arrives: content unchanged, reasoning behind a `[thinking]` header, and each tool call behind a `[tool call] <name>` header followed by its argument fragments.

```python
from swarms import Agent

def get_weather(city: str) -> str:
    """Get the current weather for a city.

    Args:
        city: Name of the city.

    Returns:
        A short weather report.
    """
    return {"Paris": "18C and sunny", "London": "12C and raining"}.get(city, "15C and cloudy")

agent = Agent(
    agent_name="Weather-Agent",
    model_name="gpt-5.4-mini",
    max_loops="auto",
    tools=[get_weather],
    print_on=False,
)

for token in agent.run_stream("Get the weather in Paris and London, then tell me which is warmer."):
    print(token, end="", flush=True)
```

```
[tool call] create_plan {"task_description":"Get the current weather in Paris and London...","steps":[...]}
[tool call] get_weather {"city":"Paris"}
[tool call] subtask_done {"task_id":"fetch_paris_weather","summary":"Retrieved ... 18C and sunny.","success":true}
...
[tool call] complete_task {"task_id":"main_task","summary":"...","results":"...Paris is warmer."}
```

Every streaming mode reads from the same source: callbacks, `run_stream`, `arun_stream`, the live Rich panel (thinking dimmed, tool calls in cyan) and detailed streaming, whose `token_info` dicts gain a `type` field of `content`, `reasoning` or `tool_call`. The tool-call summary and the post-MCP summary, which ran on a separate non-streaming call, now stream too. On the same live task, streamed events per run went from 0 to 63 to between 528 and 784, with all nine tool calls in the stream. The runnable version is `examples/single_agent/capabilities/streaming/auto_loop_streaming_example.py`.

Two related fixes: a `streaming_callback` now receives tokens even when `streaming_on` is off, which is how `CLAUDE.md` had always documented it ([#2473](https://github.com/kyegomez/swarms/pull/2473)), and `run(..., streaming_callback=fn)` on a `SwarmRouter` no longer crashes the swarm's constructor ([#2500](https://github.com/kyegomez/swarms/pull/2500)).

### Async fan-out with a concurrency cap

The plan in [#2959](https://github.com/kyegomez/swarms/issues/2959) is to put the fan-out structures on `Agent.arun` with a caller-settable bound. Three pieces landed.

`run_agents_concurrently_async` now awaits each agent's `arun` instead of pushing `run` onto a thread, and takes `max_concurrency` ([#3093](https://github.com/kyegomez/swarms/pull/3093)). Results stay in input order and the first exception propagates. `None` runs every agent at once; a value below 1 raises `ValueError`, because `asyncio.Semaphore(0)` would wait forever.

```python
import asyncio
from swarms import run_agents_concurrently_async

results = asyncio.run(
    run_agents_concurrently_async(agents, "Summarise today's news.", max_concurrency=8)
)
```

`CouncilAsAJudge.arun` ([#3096](https://github.com/kyegomez/swarms/pull/3096)) and `MajorityVoting.arun` ([#3111](https://github.com/kyegomez/swarms/pull/3111)) follow their sync `run` step by step: each judge or voter gets the same typed-turn view, at most `max_concurrency` call the model at once, votes and verdicts are recorded in agent order, and the return value is the same.

```python
from swarms import CouncilAsAJudge, MajorityVoting

verdict = await CouncilAsAJudge(model_name="gpt-5.4").arun(response_to_judge, max_concurrency=3)
answer = await MajorityVoting(agents=voters, max_loops=1).arun(question, max_concurrency=2)
```

`Agent.arun` itself is still `asyncio.to_thread(self.run)` until [#2711](https://github.com/kyegomez/swarms/issues/2711) is done, so each in-flight agent still holds a thread today, but only `max_concurrency` of them at once. When native `arun` lands, all three run on the event loop with no further change.

### `AgentRearrange` runs whole swarms as steps

`AgentRearrange` now takes whole swarms in `agents=`, next to ordinary agents, so `SwarmRearrange` is no longer needed and is deleted ([#2593](https://github.com/kyegomez/swarms/pull/2593)). Anything that has a `name` and a `run(task)` method can appear in a flow, in a sequential step, in a parallel step, more than once, and under `run_stream`.

```python
from swarms import AgentRearrange, ConcurrentWorkflow

research_team = ConcurrentWorkflow(name="Research-Team", agents=[analyst_a, analyst_b])
review_team = AgentRearrange(name="Review-Team", agents=[editor, checker], flow="Editor -> Checker")

pipeline = AgentRearrange(
    agents=[planner, research_team, review_team],
    flow="Planner -> Research-Team -> Review-Team",
)
pipeline.run("Assess the HBM supply outlook for 2027.")
```

A nested swarm receives the whole shared conversation so far as its task, the same context an agent gets. If it returns its full history, all of that goes into the outer conversation, so give the inner swarm `output_type="final"` to record only its answer. The original object stays available as `pipeline.agents[i].swarm`.

### One `AgentLoader` for Markdown, CSV, JSON and YAML

Agent loading was spread across `AgentLoader`, `CSVAgentLoader`, `MarkdownAgentLoader` and `create_agents_from_yaml`, with four overlapping schemas and a hard-coded list of allowed model names. It is now one class with one pydantic schema, `AgentConfig`, whose field names are `Agent` parameters ([#2750](https://github.com/kyegomez/swarms/pull/2750), [#2759](https://github.com/kyegomez/swarms/pull/2759)).

```python
from swarms import AgentLoader, load_agent_from_markdown, load_agents_from_markdown

loader = AgentLoader(concurrent=True, max_workers=8)

agents = loader.load_agents_from_markdown("agents/")  # every .md in a directory, in sorted order
agents = loader.auto("team.yml")                      # .md, .yaml, .yml, .csv or .json, any case
agents = loader.load_agents_from_csv("team.csv", model_name="gpt-5.4-mini")  # overrides for every agent
result = loader.load_agents_from_yaml("swarm.yaml", return_type="swarm")     # runs the configured SwarmRouter

loader.create_agent_file("team.json", [
    {"agent_name": "Researcher", "system_prompt": "You research.", "max_loops": "auto"},
    {"agent_name": "Writer", "system_prompt": "You write.", "model_name": "gpt-5.4-mini"},
])

researcher = load_agent_from_markdown("agents/researcher.md")
```

Unset fields fall back to the `Agent` defaults instead of each loader's own (the CSV loader used to turn `autosave` on and the Markdown loader set `context_length=100000`). Any model name is accepted. Aliases keep existing files loading: `name`, `description`, `model`, `dynamic_temperature` and `streaming`. Unknown keys pass through to `Agent`. `max_loops: auto` is accepted in every format ([#2757](https://github.com/kyegomez/swarms/pull/2757)), results come back in file order ([#2730](https://github.com/kyegomez/swarms/pull/2730), [#3064](https://github.com/kyegomez/swarms/pull/3064)), `AgentLoader(concurrent=False)` is honoured, and `auto()` reads back every format `create_agent_file` writes ([#2767](https://github.com/kyegomez/swarms/pull/2767)). A nested `model:` block in YAML (`model_name`, `temperature`, `max_tokens`) is now applied; it had been passed to `Agent(model=...)` and ignored.

### Wide layers and fan-outs run at full width

`ConcurrentWorkflow` capped its default pool at 32 agents, and `GraphWorkflow` sized its pool to 95% of CPU cores. Model calls are network-bound, so CPU count is the wrong limit: on a 12-core machine a 100-node layer ran in waves of 11.

ConcurrentWorkflow(agents=hundred_agents)                 # all 100 at once (was 32)

### One flat model loop

A failed model call was retried in three stacked layers: litellm's own `num_retries`, an attempt loop in `Agent._run`, and a recursive fallback chain in `LLMManager`. With the default `retry_attempts=3`, one dead endpoint could cost **up to 12 calls per model** before the agent gave up. The recursion also logged every failure once per frame, a bug in a tool re-ran the whole task on the next model, and `retry_attempts` was set as a litellm module global that litellm clears after the first retried call, so later calls in the same process were never retried ([#2811](https://github.com/kyegomez/swarms/pull/2811)).

```python
from swarms import Agent
from swarms.structs.agent import AgentLLMError

agent = Agent(
    agent_name="Analyst",
    model_name="claude-sonnet-5-5",
    fallback_models=["claude-sonnet-5-5", "gpt-5.4", "gemini/gemini-2.5-pro"],  # primary first
    retry_attempts=3,   # retries per model, made by the client: 4 calls at most
)

try:
    agent.run("Summarise the latest FOMC statement.")
except AgentLLMError as error:
    print("every model failed:", error.__cause__)
```

Now the client owns retries (`retry_attempts` travels with every request as `num_retries`, and rate limits back off exponentially), and `Agent.run` walks `fallback_models` in one flat loop. Only an `AgentLLMError` moves it to the next model; any other error raises at once. Every run starts from the primary model again, where a successful fallback used to leave the agent switched for good. `fallback_models` is the whole chain, so list the primary first: when it is set, `model_name` is replaced by its first entry. `fallback_model_name` is folded into `fallback_models` at construction, and the caller's `messages` now reach the fallback model ([#2806](https://github.com/kyegomez/swarms/pull/2806)).

### The system prompt is the one you asked for

`Agent()` without a `system_prompt` used to send a built-in 1,111-character persona with the current minute stamped into it. That persona changed what every agent said, and because the text changed every minute, it also broke provider prompt caching for agents built in different minutes. An autonomous agent sent it in front of its own 10,606-character prompt, plus a loop prompt that rendered as "loop number {current_loop} out of auto" ([#2738](https://github.com/kyegomez/swarms/pull/2738), [#2944](https://github.com/kyegomez/swarms/pull/2944)).

| `system_prompt` | `max_loops=1` | integer `max_loops >= 2` | `max_loops="auto"` |
|---|---|---|---|
| not passed | **no system message** | the loop prompt | the autonomous prompt |
| your text | your text | your text, then the loop prompt | your text, then the autonomous prompt |

```python
from swarms import Agent
from swarms.prompts.agent_system_prompts import build_agent_system_prompt

Agent(model_name="gpt-5.4")                                       # sends only your turns
Agent(model_name="gpt-5.4", system_prompt=build_agent_system_prompt())  # the old persona, if you want it
```

Two fixes made the remaining prompts honest. `safety_prompt_on=True` stored the safety prompt in the conversation's history, where it looked applied, but never sent it ([#2902](https://github.com/kyegomez/swarms/pull/2902)). And an agent with no system prompt no longer seeds an empty `System` row that showed up in every output type and autosave ([#2983](https://github.com/kyegomez/swarms/pull/2983)).

### Claude 5 and the current model generation

Current Claude models reject a sent `temperature` with HTTP 400, and Opus 5.5 rejects every sampling parameter. v16 fixed the default `Agent` path; InterLink fixed the rest.

- **Every remaining hard-coded temperature is `None`** ([#2444](https://github.com/kyegomez/swarms/pull/2444)): `swarms chat`, `ReasoningDuo`, `IterativeReflectiveExpansion`, `ContextCompressor`'s summarizer, Markdown agents, `MultiAgentRouter`, `ModelRouter` and `AutoSwarmBuilder`.
- **`top_p` defaults to `None`** ([#2443](https://github.com/kyegomez/swarms/pull/2443)), because the routers sent `temperature` and `top_p=1.0` together, a pair current Claude models refuse.
- **Prompt caching no longer stacks `cache_control` markers.** The wrapper marked the caller's own message dicts, so every loop kept one more marker: 3, 4, 5, 6, 7 per request, against Anthropic's limit of 4. It is now 3 every time ([#2443](https://github.com/kyegomez/swarms/pull/2443)).
- **`ModelRouter` routes to models that exist** ([#2604](https://github.com/kyegomez/swarms/pull/2604), [#2605](https://github.com/kyegomez/swarms/pull/2605)). Most of its table was retired or uncallable (`google/gemini-pro` is not even a litellm provider prefix). It now lists `claude-fable-5-1`, the 5.5 models, `gpt-5.4`, `gpt-5.4-mini`, `gemini-2.5-pro`, `deepseek-v4-pro`, `mistral-large-latest`, `groq/openai/gpt-oss-120b` and two OpenRouter flagships, sends no temperature to Anthropic, and takes a `model_name` for the routing model (default `gpt-5.4`, where `gpt-4o` had been hard-coded and the parameter ignored).
- **Retired defaults replaced.** `AgentJudge`, `ReflexionAgent` and the three `GKPAgent` classes defaulted to `openai/o1`, which OpenAI shut down on October 23 ([#2964](https://github.com/kyegomez/swarms/pull/2964)). `ReasoningDuo` ran its main agent on a hard-coded model whatever `model_name` said, and its reasoning agent on `gpt-4o`, so asking for Claude silently billed OpenAI ([#2622](https://github.com/kyegomez/swarms/pull/2622), [#3067](https://github.com/kyegomez/swarms/pull/3067)).
- **`random_models_on=True` calls the model it picks.** It picked a random model for the label and kept calling the original ([#2535](https://github.com/kyegomez/swarms/pull/2535)).
- **`MessageTransforms` uses the real context window.** It assumed 4,096 tokens for every Claude and Gemini model, so `transforms=TransformConfig(enabled=True)` cut a 1M-token model's history once it passed 4k ([#2632](https://github.com/kyegomez/swarms/pull/2632)), and it dropped the system prompt and `MEMORY.md` preamble when trimming, because it matched only a lower-case `system` role ([#2977](https://github.com/kyegomez/swarms/pull/2977)).

### Conversations: cheaper to read, built from one history

- **Token counts are cached per message** ([#2477](https://github.com/kyegomez/swarms/pull/2477), [#2503](https://github.com/kyegomez/swarms/pull/2503), [#2552](https://github.com/kyegomez/swarms/pull/2552)). Every history read tokenized the whole transcript, and agents read it several times per loop. Reading 200 messages (about 65k tokens) went from 28 ms to 2 ms, and from 49 ms to 3 ms when trimmed to a window. `ContextCompressor` tokenized the whole history on every check, so over 160 turns it tokenized 11.35 million characters; it now tokenizes 0.41 million. A first read of 1,000 short messages into a 200-token window makes 15 tokenizer calls instead of 1,007. `Conversation.count_history_tokens()` is public, and the compressor now counts with the agent's own tokenizer.
- **`Transcript` is folded into `Conversation`** ([#2557](https://github.com/kyegomez/swarms/pull/2557)). `Agent._run` kept a second history next to `short_memory` and sent that one. Every request is now built from `short_memory.to_messages(...)`. The visible effects: the "Current Internal Reasoning Loop n/m" marker rows are gone, a second `run()` sends earlier tool calls as real tool calls rather than stringified text, and a compression summary actually reaches the request in the integer loop. Net −154 lines.
- **The compression call is counted in `agent.usage`** ([#2722](https://github.com/kyegomez/swarms/pull/2722)). It is usually the single largest request in a long run, and it was the one missing from the totals.
- **`"str"`, `"string"` and `"all"` output types return the whole conversation** ([#3100](https://github.com/kyegomez/swarms/pull/3100)). They returned the model-context view, trimmed to 8,192 tokens and cut mid-word, so once a transcript passed about 8k tokens, `AgentRearrange` and `SequentialWorkflow` (whose default is `"all"`) silently dropped the task and the first agents' answers. The context sent to models is still trimmed as before.
- **Loading and exporting do what they say.** `Conversation(load_filepath=...)` ignored the file ([#2460](https://github.com/kyegomez/swarms/pull/2460)), and `export_conversation("backup.json")` overwrote the autosave file instead of writing `backup.json` ([#2532](https://github.com/kyegomez/swarms/pull/2532)).

### MCP

- **`mcp_url` is never run as a command** ([#2724](https://github.com/kyegomez/swarms/pull/2724)). A scheme-less `mcp_url` was treated as a stdio server: the string was split on spaces and launched, with the host's full environment, every API key included. Anyone who controlled an agent's `mcp_url` (a request body, a Markdown agent file's frontmatter, a config) could run a command. Stdio servers now start only from an explicit `MCPConnection(command=..., args=[...])`, with the MCP SDK's minimal default environment plus the connection's own `env`.

  ```python
  from swarms import Agent, MCPConnection

  agent = Agent(
      agent_name="Local-Tools",
      model_name="gpt-5.4",
      mcp_config=MCPConnection(
          command="python",
          args=["server.py"],
          env={"API_KEY": "env:API_KEY"},   # pass what the server needs, explicitly
      ),
  )
  ```

- **Two agents sharing one `MCPConnection` keep their own credentials** ([#2975](https://github.com/kyegomez/swarms/pull/2975)). The manager wrote its defaults onto the caller's object, so on the PR's repro `bob` authenticated to the server with `alice`'s token. Each manager now works on a copy.
- **OAuth works with servers that serve their resource at a path** ([#2905](https://github.com/kyegomez/swarms/pull/2905)), the usual `/mcp` setup. The provider was given the server's origin, so the SDK rejected the advertised resource before reaching the authorization server.
- **A single-server agent stops sending local tool calls to the MCP server** ([#2445](https://github.com/kyegomez/swarms/pull/2445)), which answered `Unknown tool`, and the model read that as the tool's result.
- **`MCPDeployer` can start again** after `stop()`, after a `with` block, or after a first `start()` failed on a busy port, which had used up the MCP session manager before the socket was even bound ([#2974](https://github.com/kyegomez/swarms/pull/2974)).

### Telemetry: everything a run did, compressed, and off means off

Telemetry is on by default, as it was in v16. What it records changed substantially in this release, so here it is plainly.

**What is recorded** ([#2504](https://github.com/kyegomez/swarms/pull/2504), [#2505](https://github.com/kyegomez/swarms/pull/2505)). Every traced call records all of its arguments (`swarms.inputs`) and the full conversation of the structure that made it (`swarms.conversation`). Every `Agent.run` records the tokens it used (`swarms.usage.*`). Every model call gets its own `Agent.llm_call` span with its latency, model, finish reason, the exact request (`swarms.request`) and the provider's full response (`swarms.response`). `swarms.output` is recorded whole. The old `log_agent_data` snapshots, which arrived truncated mid-JSON once a history passed 65,536 characters, are removed.

**What is redacted** ([#2501](https://github.com/kyegomez/swarms/pull/2501)). Any dict key that names a credential (ending in `key` or `token`, or containing `secret`, `password`, `authorization` or `oauth`, plus headers and `env`) is replaced with `<redacted>` everywhere, including inside an `MCPConnection`. The error log no longer dumps the agent's whole state. **Message text and argument values are not scrubbed**, so a secret you paste into a prompt is sent as written.

**How to turn it off:**

```bash
export SWARMS_TELEMETRY_ON=False
```

Off now means off: `trace_run` returns your methods undecorated and no OpenTelemetry module is imported ([#2945](https://github.com/kyegomez/swarms/pull/2945), [#2967](https://github.com/kyegomez/swarms/pull/2967)). The switch is read when swarms is imported, which includes a `.env` file.

**How it is sent.** Exports go to `https://telemetry.swarms.world`, compressed with zstd and falling back to gzip ([#2506](https://github.com/kyegomez/swarms/pull/2506), [#2544](https://github.com/kyegomez/swarms/pull/2544)), every 500 ms during the run rather than all at exit ([#2869](https://github.com/kyegomez/swarms/pull/2869)), over a connection opened at setup. The exit flush is capped at one second, so an unreachable collector no longer holds the process for eight ([#2484](https://github.com/kyegomez/swarms/pull/2484)), and a failed export or bootup step never prints or raises ([#2856](https://github.com/kyegomez/swarms/pull/2856)). On a 150-run workload, 283 of 301 spans left during the run and the exit flush fell from 441 ms to 44 ms.

|---|---|---|---|

### Tools

- **`tool_call_summary` defaults to `False`** ([#2432](https://github.com/kyegomez/swarms/pull/2432)). After every tool call the agent made a second model call to summarise the output into `short_memory`, which the model never read. That cost 2.0 to 2.8 seconds per tool turn on Haiku. A tool turn is now one model call.
- **Nested Pydantic parameters produce valid schemas** ([#2541](https://github.com/kyegomez/swarms/pull/2541)). A tool taking `items: list[LineItem]` shipped a `$ref` that pointed nowhere, because each parameter's `$defs` stayed inside the parameter. They are hoisted to the root. A model with fields named both `type` and `title` no longer loses `title` from its properties ([#2462](https://github.com/kyegomez/swarms/pull/2462)).
- **A list of Anthropic-style tool calls runs each tool once**, not twice ([#2570](https://github.com/kyegomez/swarms/pull/2570)), and `Agent(list_base_models=[...])` constructs and sends real schemas instead of raising `TypeError` and then double-encoding them ([#2571](https://github.com/kyegomez/swarms/pull/2571), [#2577](https://github.com/kyegomez/swarms/pull/2577)).
- **A one-CPU host can build agents.** `int(os.cpu_count() * 0.8)` is 0 on one core, so every `Agent(tools=[...])` raised on a 1 vCPU container. Tool schemas are now built in a plain loop, and `HeavySwarm` uses a helper that never returns less than 1 ([#2468](https://github.com/kyegomez/swarms/pull/2468), [#2598](https://github.com/kyegomez/swarms/pull/2598)).
- **The autonomous loop reuses its client and tool schemas across runs** ([#2521](https://github.com/kyegomez/swarms/pull/2521)): no client rebuilds after the first run (it was two per run) and an autonomous `run()` with ten tools spends 0.69 ms in swarms instead of 1.83. `max_subtask_iterations` now counts LLM calls as documented; it counted subtasks, so the real ceiling was 20 times the stated one ([#2308](https://github.com/kyegomez/swarms/pull/2308)).

### `CronJob`

Four fixes make a `CronJob` stoppable and restartable. `stop()` waits on an event instead of a one-second sleep, so stopping ten idle jobs takes under a second instead of seven ([#2488](https://github.com/kyegomez/swarms/pull/2488)). A stopped job restarts without a stale schedule that ran the task twice per tick, without a spent error budget, and without a second scheduler thread ([#2567](https://github.com/kyegomez/swarms/pull/2567)). And a job can stop itself from its own agent or callback, which had raised `cannot join current thread` ([#2639](https://github.com/kyegomez/swarms/pull/2639)):

```python
from swarms import CronJob

runs = []

def report(output, task, metadata):
    runs.append(output)
    if len(runs) == 3:
        job.stop()   # safe from inside the job now
    return output

job = CronJob(agent=agent, interval="1hour", callback=report)
job.run("Summarise the overnight alerts.")
```

### Routers and smaller structures

- **`SwarmRouter` builds each swarm the way its docs describe.** `MixtureOfAgents` uses the last agent as the aggregator only, where it also ran as a worker and judged its own answer ([#2732](https://github.com/kyegomez/swarms/pull/2732)). `RoundRobin` returns the router's `output_type` ([#2731](https://github.com/kyegomez/swarms/pull/2731)). `GroupChat` gets `max_loops` agent turns, where the default of 1 had meant zero turns, because the user's message counted as the first ([#2755](https://github.com/kyegomez/swarms/pull/2755)).
- **`AutoSwarmBuilder.initialize_swarm_router` tells the boss which agents it has** ([#2898](https://github.com/kyegomez/swarms/pull/2898)), so its flow names real agents instead of invented ones that `AgentRearrange` then rejected.
- **`TreeAgent` routing works** ([#2620](https://github.com/kyegomez/swarms/pull/2620), [#2990](https://github.com/kyegomez/swarms/pull/2990)). Its top keywords were words like `you`, `are` and `a`, matched as substrings, so the first agent in a tree claimed every task. And `TreeAgent(name=...)`, the documented spelling, built a nameless agent whose `ForestSwarm.run` returned `None`.
- **`AdvisorSwarm`** records turns under the agents' own names, so a custom executor no longer reads its own code back as someone else's ([#2543](https://github.com/kyegomez/swarms/pull/2543)). **`SelfMoASeq`** passes `max_tokens` to its agents and stops generating samples it will never aggregate ([#3065](https://github.com/kyegomez/swarms/pull/3065)). **`AgentRouter`** stopped embedding history text with a space between every character ([#2597](https://github.com/kyegomez/swarms/pull/2597)). **`AgentRegistry.find_agent_by_id`** works ([#2773](https://github.com/kyegomez/swarms/pull/2773)). Raw base64 images are recognised again on Python 3.12 and later ([#2809](https://github.com/kyegomez/swarms/pull/2809)).
- **The CLI**: `swarms init` updates an existing `.env` in place instead of overwriting it and deleting unrelated keys ([#3057](https://github.com/kyegomez/swarms/pull/3057)), `swarms load-markdown` loads a directory ([#2766](https://github.com/kyegomez/swarms/pull/2766)), and an unknown command exits with status 2 ([#2760](https://github.com/kyegomez/swarms/pull/2760)).

## Upgrade Notes

1. **Give your agents a system prompt.** `Agent()` without one now sends none. If your agents relied on the built-in persona, pass `system_prompt=build_agent_system_prompt()` from `swarms.prompts.agent_system_prompts`.
2. **Expect swarms to raise.** `HeavySwarm`, `MixtureOfAgents`, `MajorityVoting`, `AuctionSwarm` and parallel `AgentRearrange` steps now raise where they returned an error string. Catch the exception, or run them under `SwarmRouter(fallback_swarms=[...])`, which now actually falls back. Provider errors arrive as `AgentLLMError` with the original as `__cause__`.
3. **Turn file output back on where you need it.** Pass `autosave=True` to `SequentialWorkflow`, `ConcurrentWorkflow`, `AgentRearrange` or `SpreadSheetSwarm`, and set `SWARMS_LOG_FILES=True` for log files.
4. **Replace removed structures and loaders.** `SwarmRearrange` becomes `AgentRearrange(agents=[...swarms])`; `create_agents_from_yaml`, `CSVAgentLoader` and `MarkdownAgentLoader` become `AgentLoader`; `ImageAgentBatchProcessor` lives in the vision examples.
5. **Search for removed keyword arguments.** `multi_modal`, `sop`, `sop_list`, `output_cleaner`, `agents_config`, `memory_system`, `shared_memory_system` and `shared_memory` are now ignored silently. `n`, `idle_timeout`, `auto_generate_prompts` and `output_metadata` raise `TypeError`. `bulk_run` and the fallback-chain methods are gone.
6. **Set a concurrency cap if your provider rate-limits you.** `ConcurrentWorkflow` and `GraphWorkflow` now run every agent in a layer at once: use `max_workers` and `max_parallel_nodes`.
7. **Move stdio MCP servers to `MCPConnection(command=..., args=[...])`** and pass the environment variables they need explicitly.
8. **Check what streaming consumers receive.** Callbacks and `run_stream` now include tool-call and thinking text behind `[tool call]` and `[thinking]` headers.
9. **Review telemetry.** It records full conversations, arguments, requests and responses, with credential-named keys redacted and message text sent as written. Set `SWARMS_TELEMETRY_ON=False` to opt out.
10. **Install `swarms[fast]`.** RouteHub and rustworkx are drop-in, and `SWARMS_LLM_BACKEND=litellm` switches back.

## What's Next

The open threads are written down rather than implied:

- **Ready-queue scheduling for `GraphWorkflow`** ([#3102](https://github.com/kyegomez/swarms/issues/3102)). Both swarms and LangGraph wait for a whole layer before starting the next, so on the benchmark's staggered graph both take 1.61 s where 0.55 s is possible. Starting each node the moment its own dependencies finish is the next large speedup.
- **Native async `Agent.arun`** ([#2711](https://github.com/kyegomez/swarms/issues/2711)). Until it lands, every awaited agent still holds a thread; after it, the async fan-out helpers in this release run on the event loop with no further change, and the rest of [#2959](https://github.com/kyegomez/swarms/issues/2959) can follow.
- **A typed event stream and an `on_error` policy for `GraphWorkflow`** ([#3103](https://github.com/kyegomez/swarms/issues/3103), [#3104](https://github.com/kyegomez/swarms/issues/3104)), so a caller can watch a graph run node by node and choose whether a failed node stops it.
- **The autonomous loop's own transcript.** #2557 moved the integer loop onto `short_memory`; `max_loops="auto"` still keeps a separate request `Conversation`, because its tool handlers write prose copies of results into memory (the rest of [#2386](https://github.com/kyegomez/swarms/issues/2386)).
- **`HierarchicalSwarm` and `MixtureOfAgents` pools** still default to 95% of CPU cores, the limit #2956 and #2957 removed elsewhere.
- **The litellm pin.** The 22 remaining Docker Scout findings are all in litellm's proxy server and clear with litellm 1.88.6 or newer, a jump of twelve minor versions that needs its own test pass.
- **Telemetry payload size.** Each run span re-sends the conversation so far, so export size grows with the square of the turns. zstd keeps it under the collector's cap today; sending only the messages new since the last span would remove the growth.
- **Live checks for the email channels.** `SmtpChannel`'s thread search has not yet been run against Gmail, Microsoft 365 and Dovecot servers, and `AgentMailChannel` has not been run on a paid plan or the EU host.
- **Channel documentation.** The docs site's Comms Channel page is in an open docs PR; until it merges, `examples/channel_examples/` is the reference.
