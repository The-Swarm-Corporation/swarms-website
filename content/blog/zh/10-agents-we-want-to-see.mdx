# 我们希望在 Swarms Marketplace 上看到的 10 个智能体

[Swarms Marketplace](https://swarms.world) 上的智能体多到一周都看不完，而其中很大一部分做的都是同样几件事。与此同时，来自 Google、PayPal、Neon、PagerDuty、Perplexity 等厂商的 [25 个官方 MCP 服务器](/blog/25-new-mcp-servers-mcp-depot)于 10 月 20 日一次性上架。服务器已经在那里了，能把它们用起来的智能体大多还没有出现。

这是一份愿望清单：我们认为应该存在、但目前还没有的十个智能体，每一个都附有简短的规格说明、应使用的 MCP 服务器，以及适合它的 [Swarms API 架构](/blog/swarm-architectures-explained)。这些就是我们会推荐展示的商品，也正是我们的[竞赛](/blog/agent-competitions-swarms-marketplace)想要推到大家面前的那类作品。做出一个，我们想看到它。

## 目录今天的样子

[Explorer](/blog/swarms-marketplace-explorer) 提供实时数字。在那篇文章写作时（2026 年 10 月 17 日），市场上共有来自 808 位卖家的 6,400 个商品：5,576 个智能体、773 个提示词和 46 个工具。其中 214 个商品为付费，996 个已代币化，24 个智能体对外提供 MCP 服务器。

智能体数量是工具的一百多倍，所以智能体这个类型是最拥挤的地方。而只有 24 个智能体提供 MCP 服务器，这意味着市场上的智能体与人们实际用来经营业务的系统之间的连接非常薄弱。Explorer 按商品类型统计，所以下面这句是我们浏览注册表时的印象：通用助手、角色人设和交易相关的智能体很多，而能登录某个具体的业务系统、完成一件边界清晰的工作的智能体非常少。

后一类智能体所需的基础设施已经成批到位。[mcp_depot](https://swarms.world/users/mcp_depot) 在 10 月 20 日发布了 25 个由厂商托管的服务器，使其目录达到 55 个，覆盖数据库、支付、搜索、事故管理、项目管理、会议、内容和基础设施。下面的每个智能体都至少用到其中一个。

## 这十个智能体

每一个都有一位有预算的买家，以及可以被核验的输出。[Auto Agent Builder](/blog/introducing-auto-agent-builder) 可以用一次调用把下面任何一段问题描述变成一份初稿团队配置。

### 1. 代码库迁移规划器（Codebase Migration Planner）

**问题。** 每个团队都有一个一直在拖延的迁移：框架大版本升级、数据库搬迁、CI 系统更换。难的是那份计划：列出每一个受影响的文件，把步骤排好顺序让系统在过程中持续可用，并说明如何回滚。没人愿意写它，于是迁移一拖再拖。

- **输入：** 一个代码仓库，源与目标，以及零停机等约束。
- **输出：** 按步骤排序、带每步风险的计划，文件级变更清单，回滚章节，以及以工程师人天计的估算。
- **MCP 服务器：** Jina AI 读取目标的文档和变更日志；Neon 在临时分支上试跑每一次 schema 迁移，再写进计划；Postman 比对 API 集合的差异。
- **架构：** `PlannerWorkerSwarm`。步骤无法事先列全，内置的评审者会不断重新规划，直到计划覆盖目标。

**演示：** 指向一个公开仓库并发布它写出的计划，包括在 Neon 分支上试跑失败的那一步。

**定价：** 一次性付费商品，刷卡购买。一份能省下资深工程师两天时间的计划，价值远高于一般智能体的价格。

### 2. 发票对账智能体（Invoice Reconciliation Agent）

**问题。** 一家通过 PayPal 开发票、在柜台用 Square 收款的企业，月底会拿到三份对不上的记录。有人要手工逐行匹配。匹配得上的部分很简单，例外才是真正的工作。

- **输入：** 日期范围、银行对账单导出文件，以及支付账户的访问权限。
- **输出：** 已匹配的账目，按原因分组的例外清单（部分付款、退款、手续费不符、重复），以及给业主看的通俗摘要。
- **MCP 服务器：** PayPal 提供发票、付款、争议和报表；Square 提供付款和订单（演示时用只读模式）；Box 读取会计师存放对账单的文件夹。
- **架构：** `SequentialWorkflow`。提取、归一、匹配、解释。每一步都依赖上一步，每个智能体一轮输出天然就是一份审计记录。

**演示：** 一个合成的月份，200 笔交易加十几个预先埋入的例外，和智能体给出的清单并列展示。

**定价：** 一次性付费商品，刷卡购买。[法币支付通道](/blog/fiat-payments-live-swarms-marketplace)就是为这种买家准备的：用公司账报销一个工具，从不需要考虑钱包。

### 3. 值班事故总结器（On-Call Incident Summarizer）

**问题。** 事故在凌晨 3 点结束，复盘报告要在上午 10 点的站会上交。手头只有一条 PagerDuty 时间线、一堆聊天记录和几张客服工单，而把它们整理成报告的活，落在了房间里最疲惫的那个人身上。

- **输入：** 一个 PagerDuty 事故 ID，可选附上聊天记录导出。
- **输出：** 带时间戳的时间线、客户影响章节、标注为假设的可能原因，以及已录入任务系统的后续事项。
- **MCP 服务器：** PagerDuty 提供事故、服务、值班人员和升级路径；Intercom 查找提到此次故障的客服对话；ClickUp 或 monday.com 用来录入后续事项。
- **架构：** `MixtureOfAgents`。时间线、影响和后续事项三个智能体并行阅读同一份证据，聚合器写出那份直接贴进站会的报告。

**演示：** 把一个沙盒事故变成两页报告，后续事项在看板上可见。

**定价：** 刷卡付费，或代币化并启用 Vault Mode，让值班轮值组持有代币并获得访问权（[Vault Mode 的工作方式](/blog/vaulted-tokenized-agents-competition)）。

### 4. SQL 审查智能体（SQL Review Agent）

**问题。** 分析查询写一次，跑一辈子。一条每五分钟全表扫描 ClickHouse 的查询，或一个读取一 TB 数据只返回十行的 BigQuery 作业，就是一笔没人审查的隐形账单。

- **输入：** 一条 SQL 语句或 dbt 模型，以及目标数据库的连接。
- **输出：** 三份独立评审（正确性、成本、安全性），必要时给出重写后的查询，以及每位评审者依赖的 schema 事实。
- **MCP 服务器：** ClickHouse 和 Neon 提供 schema 和只读执行；Google BigQuery 提供同样的能力。
- **架构：** `ConcurrentWorkflow`。三份评审彼此独立，买家也希望分别查看，所以没有合并的必要，也没有理由串行执行。

**演示：** 十条公开数据集查询的前后对比，扫描字节数由数据库本身报告。

**定价：** 免费商品加代币化发行。开发者会在每一条查询上运行它，这种使用模式更适合从每笔交易中分成，而不是一次性售价。

### 5. 研究综合器（Research Synthesizer）

**问题。** 大多数研究智能体返回一串链接，每个下面一段话。决策者需要的是一个立场：证据说明了什么，来源在哪里有分歧，哪些论断经原始来源核实过，还有什么是未知的。

- **输入：** 一个问题、一个深度设置，可选指定必须纳入的来源。
- **输出：** 带编号引用的简报、分歧对照表、无法核实的论断清单，以及 Markdown 格式的来源列表。
- **MCP 服务器：** Perplexity 负责搜索、带引用的回答和深度研究；Jina AI 把网址读成 Markdown、提取 PDF 并搜索 arXiv；Apify 负责需要爬虫的来源。
- **架构：** `HeavySwarm`。研究、分析、备选方案和核验由各自独立的工作者完成，再由综合智能体写出简报。这是清单里最贵的架构，也是正确的那个。

**演示：** 一个有争议的技术问题，搜索结果前几名互相矛盾，让分歧对照表来说话。

**定价：** 一次性付费商品，刷卡购买，附带一个展示输出格式的免费配套提示词。

### 6. 提示词合规检查器（Prompt Compliance Checker）

**问题。** 市场上的每个提示词现在都带有[安全评分](/blog/prompt-security-scores-swarms-marketplace)，能抓出恶意指令。但还没有东西按公司自己的规则检查提示词：受监管的用语、不允许做出的声明、不得索取的数据、披露要求。金融、医疗和法律团队今天还在手工做这件事。

- **输入：** 一个提示词，以及一份政策文件或规则集（“不提供投资建议”“不收集健康数据”“披露 AI 参与”）。
- **输出：** 每条规则的通过或不通过，引用出问题的片段，给出合规措辞的修订稿，以及每条发现的简短理由。
- **MCP 服务器：** Box 原地读取公司的政策文件；Jina AI 拉取规则引用的监管原文。
- **架构：** `MajorityVoting`。每条规则都是一个是或否的问题，独立投票者降低单一模型的方差，票数本身就是证据。CouncilAsAJudge 固定的六个维度在这里是错误的评判标准。

**演示：** 从公开注册表中取二十个提示词，按同一份已发布的政策检查，展示结果表和修订稿。

**定价：** 一次性付费商品，刷卡购买，面向合规和平台团队。

### 7. 会议转工单智能体（Meeting-to-Tickets Agent）

**问题。** 一场产品会议产生八个决定和五项行动事项，只有两项进了任务系统。录音工具已经会做摘要，缺的那一步是把摘要变成贴合看板结构的工单，并且不和已有的工作重复。

- **输入：** 一份转录文本或录音 ID，以及目标列表或看板。
- **输出：** 带标题、描述、负责人和截止日期的工单草稿，每一条链接到它来自的转录段落，外加因已有匹配工单而跳过的事项。
- **MCP 服务器：** Fireflies.ai 提供转录、摘要、行动事项和参会者；ClickUp 或 monday.com 读取看板并创建工单。
- **架构：** `SequentialWorkflow`。提取决定、起草、与看板去重、录入。顺序固定，每一步都依赖上一步。

**演示：** 一场 40 分钟的会议，看板的前后对比，以及它拒绝创建的那条重复工单。

**定价：** 一次性付费商品，刷卡购买，定在智能体价格区间的低端，让团队负责人无需审批就能买。

### 8. 本地化质检智能体（Localization QA Agent）

**问题。** 翻译一个网站是容易的那一半。成本在检查上：字符串撑爆按钮，不该翻译的产品名被翻译了，同一个术语出现三种译法。十种语言的人工质检比翻译本身更贵。

- **输入：** 源语言和目标语言内容（CMS 集合或字符串文件）、受保护术语表、目标区域设置。
- **输出：** 按页面和字符串列出的问题清单（术语、语体、长度、未翻译的受保护术语），每个问题的修改建议，以及按区域的质量摘要。
- **MCP 服务器：** Webflow 直接读取页面和 CMS 集合；Box 存放术语表和字符串文件；Canva 用于带文字的营销素材。
- **架构：** `GroupChat`。一个语言专家、一个术语智能体和一个布局约束智能体共同审阅一页，长度约束会改变语言专家的修改方案。控制在三到四个智能体。

**演示：** 一个双语的公开 Webflow 网站，展示问题清单和至少一个被它抓到的受保护术语。

**定价：** 一次性付费商品，或以 USDC 计价的代币化发行。[USDC 发行锦标赛](/blog/usdc-launch-championship)那篇文章解释了为什么美元定价适合有预算的买家。

### 9. 数据管道监控器（Data Pipeline Monitor）

**问题。** 数据管道的故障是悄无声息的。一张表停止更新，行数减半，一列全部变成空值，直到仪表盘看起来不对才有人发现。最昂贵的故障，是每个作业都报告成功的那种。

- **输入：** 一组表或视图及其预期的新鲜度和数据量，以及一个调度计划。
- **输出：** 每日健康报告；出现异常时，由对应的专家给出诊断（新鲜度、数据量、schema 漂移、分布偏移），并在规则要求时开一个事故。
- **MCP 服务器：** Google BigQuery 和 ClickHouse 用于检查 schema 和运行检查；PagerDuty 用于创建和批注事故；Pulumi 用于指出拥有这张坏表的资源。
- **架构：** `MultiAgentRouter`。每种异常类型都有一位专家，大多数运行只会触发其中一位，路由器没选中的智能体根本不会运行。

**演示：** 一个公开数据集，埋入一次新鲜度故障和一次数据量下降，展示路由器给出的两种不同诊断。

**定价：** 免费商品加代币化发行。采用它的团队，就是将来持有代币的人。

### 10. 资助申请与 RFP 起草器（Grant and RFP Drafter）

**问题。** 非营利组织、实验室和小供应商要回应 60 页的资助征集和招标文件，每次用不同的措辞问同样的二十个问题。答案早已存在于共享文件夹里的历次提案中，而把它们改写到这次申请里，每份要花掉资助撰写人一周的时间。

- **输入：** RFP 文件、历次提案的文件夹，以及一段关于本次提案的简述。
- **输出：** 把每个问题映射到草拟答案的需求矩阵，按资助方章节顺序排列的完整草稿，从未回答过的问题清单，以及格式检查表。
- **MCP 服务器：** Jina AI 提取 RFP 的 PDF；Box 原地搜索历次提案；Perplexity 研究资助方的优先事项和近期资助项目。
- **架构：** `HierarchicalSwarm`。主管读取征集文件，拆分成章节，把每一节连同相关的历史材料交给一位撰写者，再整合结果。如何拆分一份 60 页的文件本身就是判断题，这正是主管的职责。

**演示：** 用一组合成的历史提案回应一份真实的公开 RFP，完整展示需求矩阵。

**定价：** 一次性付费商品，刷卡购买，定在智能体价格区间的顶端。一份获得资助的提案就能回本。

## 如何让我们看到它

没有单独的提交表单。路径和每篇竞赛文章描述的一样。

1. **把它做出来，拿到真实的演示输出。** 以此开场。
2. **在 [swarms.world/launch](https://swarms.world/launch) 发布。** 选择匹配的分类和标签。如果它使用 MCP 服务器，填入服务器 URL；市场会自动给它打上 MCP 标签，并把它列在 [MCP 服务器页面](https://swarms.world/mcp-servers)上。也可以让框架替你发布，设置 `publish_to_marketplace=True` 和 `tags` 即可（[示例见此](/blog/what-is-an-agent-marketplace)）。
3. **定价。** 付费商品接受刷卡或加密货币，平台统一收取 10% 的费用，买家获得永久访问权。代币化商品从每笔交易中分成，Vault Mode 则把访问权限制给持有者。[Seller Portal](/blog/swarms-seller-portal) 会显示每种方式的收入。
4. **在竞赛窗口内发布。** 竞赛每周举行，发布只要符合当周规则就自动参赛，排行榜在 [swarms.world/competitions](https://swarms.world/competitions) 公开。第一届 Frenzy 竞赛一周内吸引了 23 个以上的发行和超过 25 万美元的交易量，之后的每一届衡量的指标都不一样。有真实买家的智能体，正是这些排行榜存在的目的。
5. **告诉我们。** 把商品页发到 [Swarms Discord](https://discord.gg/VapjxpSyHC)，并在 X 上标记 [@swarms_corp](https://x.com/swarms_corp)。两个地方我们都看，解决了这份清单上某个问题的商品，就是我们会推荐展示的那些。

市场上有 5,576 个智能体，还有 25 个全新的官方 MCP 服务器在等着它们。接下来的几百个智能体将决定这份目录读起来是一堆演示，还是一组人们愿意付费的工具。做出这十个中的一个。
