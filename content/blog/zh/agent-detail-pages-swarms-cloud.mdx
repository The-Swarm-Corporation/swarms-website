# 独立的智能体配置页面现已在 Swarms Cloud 上线

Swarms Cloud 的智能体列表过去是一条死路。它会列出你账户运行过的每一个智能体，活跃账户上往往超过一百个，然后就到此为止了。名称、描述、模型。除此之外的一切，那个真正定义智能体行为的系统提示词、它运行时的温度参数、它能调用的工具、它这个月花了你多少钱，都无法从浏览器里触达。

这个问题已经解决了。现在每个智能体都在 [cloud.swarms.ai/agents](https://cloud.swarms.ai/agents) 拥有自己的页面，并且回答的正是你当初打开这个列表时想问的问题。

## 页面的顺序，就是你需要的顺序

页面布局遵循一个人真正排查智能体时的顺序。

**先看活动。** 每个智能体页面的顶部是五个数字：最近一次运行、已记录运行次数、成功率、总 Token 数、总成本。Token 会拆分为发送与返回两部分。成本在总额之外还给出每次运行的平均值。这些数据从你真实的请求日志中汇总而来，并且只筛选这一个智能体，所以「这东西一直在干什么、又收了我多少钱」在你往下滚动之前就已经有了答案。

**然后是系统提示词。** 在这个平台上，系统提示词就是智能体本身。模型和采样参数只是包裹在它外面的旋钮。所以提示词排在配置表之前，并且做成下拉展开，因为真实的提示词往往很长。我们自己账户里就有一个智能体，系统提示词长达 35,774 个字符，如果直接内联展开，下面的一切都会被埋掉。展开后它以整页宽度完整渲染，滚动的是页面而不是提示词框，这意味着页内查找能命中其中每一个词，打印出来也是正确的。旁边配有复制按钮。

**接着是配置。** AgentSpec 的全部 34 个字段，以名称、说明、取值三列呈现。不只是你恰好设置过的那些，而是 API 接受的每一个字段，每一个都配有一行说明讲清它的作用，排列顺序遵循一个智能体被构建出来的过程：它是谁、它被告知了什么、什么在驱动它、它思考得多用力、它能触达什么、它如何被列出。

关键在于取值这一列。任何你从未设置过的字段，都会用 API 自身的默认值填在原本的空白处，因此这张表告诉你的是**下一次运行实际会发生什么**，而不只是某个人在表单里填过什么。处于默认值的行会以弱化样式显示，让那些智能体真正覆盖过的、大约八个左右的字段自然占据视觉重心，同时不隐藏任何内容。

你可以在页面头部把整份配置复制为 JSON。

## 逐次运行的上下文窗口占用

配置下方是运行历史：与 `/history` 相同的日志表格，筛选到这个智能体，支持分页、排序和导出 CSV。

展开单次运行，你会看到一个新东西。一个由一百个格子组成的网格，每格代表模型上下文窗口的百分之一，从左上角开始填充，并按发送与返回两部分着色。

这正是用其他方式很难拿到的数字。一个跑在百万 Token 模型上、每次调用只用掉八千 Token 的智能体，在这里就是一百格里亮起的一格，而看见这一点就是全部意义所在：要么你在为用不上的余量付费，要么你正在逼近上限。发送的那一半是会增长的一半。一个悄悄累积着历史的提示词，最终就是那个会耗尽空间的提示词，而这里让你逐次运行地看着它发生，而不是等到它彻底崩掉的那一次。

窗口大小取自 OpenRouter 的公开模型目录，因为 Swarms API 本身不发布模型上限。它在服务端拉取、缓存数小时，只有解析后的那个数字会到达你的浏览器。如果某个模型没有公开窗口大小，运行详情会如实说明，而不是去猜。

## 列表本身也修好了

`/agents` 页面在这个过程中改了两件事。

每一行现在都链接到对应的智能体。名称在这个平台上是自由文本，可能带有空格、标点，原则上还可能带斜杠，而 URL 能把这些原样往返还原。

另外，「最近使用」排序现在真的能用了。它此前按一个 API 从不返回的 `created_at` 字段排序，也就意味着每一行与其他行都比较为相等，排序无声地什么也没做。列表接口只记录智能体最后一次运行的时间，所以这一列现在如实地叫作 **Last used（最近使用）**，并按它排序。

## 在哪里找到它

打开 [cloud.swarms.ai/agents](https://cloud.swarms.ai/agents)，选中任意一个智能体，页面就在那里。上面的一切都读自你自己的账户：来自 `/v1/agents/list` 的配置规格，来自账户日志的运行记录。没有任何数据是合成的，也不需要事先做任何配置。

如果你有一阵子没仔细看过的智能体，成本那一列是个不错的起点。
