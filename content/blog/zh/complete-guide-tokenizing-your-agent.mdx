# 代币化你的智能体：完整指南

本指南分为两部分。第一部分是论证：为什么 AI 智能体是一种生产性资产，以及代币化对开发者到底改变了什么。第二部分是机制：发行流程中的每一个决策，按你实际遇到的顺序展开，从如何接入你的智能体，到三个开关分别应该怎么选。

如果你已经清楚自己为什么要这么做，可以直接跳到第二部分。如果你还不确定代币化是否适合你做的东西，那么第一部分才是关键，其中也包括了答案为「否」的那些情况。

---

# 第一部分：为什么要代币化

## 大多数软件并不是资产

大多数软件是一个偶尔产生收入的成本中心。

你构建它、托管它、维护它、推广它，如果这一切都顺利，你收到一笔订阅费。而一旦你停止做上述任何一件事，收入也随之停止。软件本身不会自行积累价值，你一移开视线，它就开始贬值。

AI 智能体在一个尚未被充分定价的层面上与此不同。智能体会干活。不是像电子表格那样「让工作成为可能」，而是真的执行：读文档、写代码、打电话、产出结果。这个区别比初看上去更重要，因为一个能够在你不参与的情况下反复执行工作、且其产出具有市场价格的东西，就不是一个文件，而是一项生产性资产。

## 是什么让智能体成为资产

一样东西要成为资产而不只是财物，必须具备三个属性。智能体三个都有。

**它能反复产生价值。**好的智能体不会因为被使用而被消耗。运行一千次和运行一次一样容易，而每一次运行都具有用户本可以付钱请人来完成的价值。这里的单位经济学既陌生又新颖：近乎为零的边际成本，对应由人力工资水平决定的边际价值。

**它带有可界定的权利归属。**你可以说清楚谁拥有一个智能体、谁有权获得它的产出、谁有权获得它产生的收入。这正是把一种能力变成财产的东西。

**它可以在不被销毁的前提下转移。**所有权可以易手，份额可以拆分。看好某个智能体的人可以建立仓位，不再看好的人可以退出。

传统的软件分发方式给了你第一个属性，却把后两个搞砸了。你拥有代码，但没有别人能持有其中的份额。喜欢你工具的用户没有办法拥有它成功的一部分，而你除了卖掉公司，也没有办法凭它未来的产出融到任何东西。资产存在，市场却不存在。

代币化并不是加在智能体之上的一层营销包装，而是让第二和第三个属性真正运转起来的那个缺失的机制。

## 开发者真正的问题不是能力

去和做智能体的人聊，你会反复听到同一件事：他们的智能体能用，确实做了有用的事，而几乎没有人知道它存在。

这才是当下智能体经济真正的瓶颈，值得把话说准。约束不是模型质量，而且已经有一段时间不是了。约束在于：成千上万个有能力的智能体，正由一群没有分发渠道、没有受众、也没有预算的人做出来，而目前没有任何机制能可靠地把一个好智能体连接到会使用它的人。

传统的解法都很贵。内容营销要花上几个月。付费获客要花你在有收入之前根本没有的钱。在聚合类网站上发布只会带来一天的流量，然后归于沉寂。这些做法无一例外都在要求开发者变成营销人员，而那是另一份工作，大多数开发者并不擅长，当初也不是冲着它来的。

代币化换了一条路。它不要求你去购买注意力，而是创造出让别人主动供给注意力的理由。

## 注意力：用利益一致取代广告投放

当一个人持有你智能体的份额时，他的激励就变了。他不再是一个也许会在想起来时提一嘴的被动用户，而是有了理由希望更多人知道你的项目，因为他所持有之物的价值取决于此。

这一点如果描述得不好，听起来会很功利；描述得准确，它其实非常有力。这不是关于制造声量，而是关于用户群体与利益相关者群体之间的差别。用户群体是一群从你的工作中获益的人，利益相关者群体是一群从你的工作**成功**中获益的人。这两者不同，而后者会替你完成分发。

这件事还有一个机制层面的版本。代币化的智能体拥有实时价格、实时市值、实时交易量，以及公开的排行榜名次。这些都是项目可以被那些原本并不在寻找它的人发现的界面。传统的上架方式只有一个界面：有人恰好搜索你做的东西并找到了你。而代币化的上架会在一个人们正主动寻找「正在发生变化的东西」的地方，持续产生信号。

注意力是智能体经济中稀缺的投入品。代币化是一种不必花钱购买就能获取它的方式。

## 所有权：把访问权变成持仓

代币化改变的第二件事，是开发者与用户之间的关系可以是什么样子。

在默认情况下，附着于智能体的代币是对项目成功的权利主张，而不是对智能体本身的权利主张。Vault Mode 改变了这一点。启用 Vault Mode 后，只有持有你智能体代币的人才能使用该智能体。持有不再是与产品并行的一次押注，而是你获得产品的方式本身。

这以一种有意思的方式颠倒了通常的订阅关系。在订阅模式下，钱从用户流向开发者，且是永久性的，而用户积累下来的是一叠收据。在按持仓开放访问的模式下，用户获得的是一样他可以保留的、有价格的东西，并且当这个智能体对他不再值得时，他可以退出。访问从一笔开支变成了一个仓位。

对开发者而言，这把客户转化成了利益一致的持有者。使用你智能体最频繁的人，正是持有最多的人，也正是最希望它成功的人。相比一份挂着周期性信用卡扣款的邮箱地址清单，这是一种强得多的社区结构。

## 收入：不只是数额不同，而是形态不同

第三个变化是收益的形态。

普通的付费上架，每个买家只付你一次钱。你拿到一笔固定金额，这个客户就变现完毕，你需要下一个。收入随获客规模增长，也就意味着随营销投入增长，而营销恰恰是你最不擅长的那件事。

代币化的上架，则会在你的代币每一笔交易上向你支付费用，买入和卖出双向都算，只要人们还在交易它，这笔收入就一直存在。

其中有两点在结构上与订阅不同。

第一，卖出同样让你赚钱。有人退出你的项目，在离场的路上也要付给你一笔费用。收入与换手挂钩，而不是与净流入挂钩，这意味着一个市场活跃、参与度高的项目，即使在市场情绪分化时也依然有收入。

第二，它不要求你为了持续赚钱而持续获客，它要求的是你项目的市场保持活跃。这两件事相关，但并不相同，而后者是你的持有者会共同参与的事，不是你一个人扛的事。

而且这一切你都不需要出资。代币化发行创建的是一条联合曲线，而不是需要你投入资金的流动性池。你带来智能体，不需要带钱。

## 为什么会有人投资代币化智能体

以上是开发者这一侧。问题的另一半是：交易对手方为什么愿意参与？这值得一个直接的回答，而不是一个想当然的假设。

**因为这是对一项生产性资产的早期敞口。**如果你相信智能体将承担相当比重的经济工作，那么现在被造出来的这些智能体，就是那个经济体的种子存量。多数会失败，少数会成为几千家企业赖以运转的基础设施。从历史上看，能在这么早的阶段对软件建立仓位的，只有能进入私募轮次的风险投资人。代币化智能体是第一种让任何人都能在「确实还很早」的时点获得该仓位的结构。

**因为访问权本身有价值，而持有是获得它的方式。**对于启用了 Vault Mode 的智能体，这笔账并不纯粹是投机。如果这个智能体对你有用，那么代币至少值这份有用性所值的价格，而且与订阅付费不同，你在最后还留下了一样东西。持有一个真正有生产力的智能体，等于在购买效用的同时附带了一个退出选项。

**因为在一个注意力才是约束的市场里，它是对注意力的权利主张。**智能体代币的交易量和市值，衡量的是一个项目吸引到了多少关注。在一个成千上万个智能体争夺有限关注度的经济体中，对那些正在赢得注意力的项目建立仓位，本身就是一个自洽的投资逻辑。

**因为从第一天起就有流动性。**早期软件股权之所以缺乏流动性，是因为在被收购或上市之前它没有市场，而那可能是十年之后，也可能永远不会到来。联合曲线让仓位可以立即交易。这不是一个微小的结构差异，它改变了早期参与的风险特征，因为判断错误并不意味着被套住无法脱身。

**因为基本面是可读的。**智能体会产出你可以评估的结果。你可以使用它、判断它好不好，并看到它的交易量和持有人数量。相比大多数早期资产（你买的是一份路演材料和创始人的信心），这个东西本身在你建仓之前就摆在那里供你检验。

## 代币化不是什么

一份只罗列好处的指南是推销，不是论证，所以有必要把边界讲清楚。

代币化不会让一个糟糕的智能体变得有价值。它创造的是一个市场，而市场相当擅长把东西定价到接近于零。一个没人想要的智能体，加上一个代币之后，仍然是一个没人想要的智能体加上一个代币。

它也不适合每一个项目。一个平稳、不起眼、每月被五十家公司安静付费使用的工具，作为一个直接的付费上架项目，很可能比作为一个没人交易的代币赚得更多。代币化奖励的是能吸引换手和注意力的项目。如果你项目的美德恰恰在于它枯燥而可靠，那就诚实面对这一点，并据此定价。

它也不会免除你做出好东西的必要。它改变的是谁来帮你分发，而不是它是否值得被分发。

从投资者一侧看，这些是年轻市场中的早期仓位。绝大多数早期的东西都会失败。价格会波动，有时相当剧烈，而一个智能体好用并不能保证它的代币会升值。参与者应当据此控制仓位规模。

## 哪些智能体值得代币化

以下是一些粗略的经验判断，来自实际被交易的那些项目。

产出可见、可演示的智能体，比价值不可见的智能体更有优势。如果有人能看着它工作并立刻明白它好在哪里，这种可读性会不断累积复利。

服务于特定社区的智能体，强过通用型智能体。社区有理由去协调、去在意、去持有。「任何人都可能觉得有用」作为利益相关者群体的基础，弱于「这对某一群特定的人是必需品」。

价值在于持续访问的智能体，是 Vault Mode 的有力候选。价值在于一次性使用的智能体，通常做成直接的付费上架更合适。

你打算持续改进的智能体，好过已经完工的智能体。利益相关者群体是一段随时间演进的关系，而一个明显仍在被打磨的项目，会给人留下来的理由。

# 第二部分：你在发行什么

流程中的第一个选择是上架类型，它会约束之后的一切。

**Agents（智能体）**是可运行的系统。智能体背后有一个实现，可能是代码、托管的 API，也可能是 MCP 服务器。智能体可以代币化，可以使用 Frenzy Mode，也可以使用 Vault Mode。

**Prompts（提示词）**是文本资产：一段系统提示词、一套抗越狱的指令集、一个精心调校、能产生特定行为的模板。提示词发布起来更简单，因为没有实现需要接入，只有内容。提示词可以代币化，可以使用 Frenzy Mode，也可以使用 Vault Mode，与智能体完全一致。如果你有一段能稳定做成某件有价值的事的提示词，它就是一等公民，而不是次一等的选择。

**Tools（工具）**是实用程序与集成。工具**不能**代币化。工具没有代币、没有联合曲线、没有 Frenzy Mode，也没有 Vault Mode。如果你希望发布的东西附带一个可交易的代币，请把它作为智能体或提示词发布。

**Bundles（组合包）**把多个上架项目打包成一个，并使用它自己独立的表单。

实用结论：如果代币化是你计划的一部分，那么你要发行的是智能体或提示词。

# 第三部分：接入智能体的四种方式

如果你选择了 Agent，「Agent Implementation」这一节会询问你的智能体究竟如何工作。这里有四个标签页，它们是真正不同的产品形态，而不是通往同一个终点的四条路。根据你的智能体实际在哪里运行、以及你希望买家能拿它做什么来选择。

## Code（代码）

你直接粘贴实现代码，选择语言，并列出它的依赖要求。

当你的智能体是自包含的、并且你希望别人能够阅读、运行和改造它时，这是正确的选择。买家拿到的是真正的源码。没有需要维持在线的端点，没有需要保障的可用性，发布之后也没有基础设施成本落在你身上。一旦售出，它就永远可用，与你是否还在运行什么无关。

当价值在于逻辑本身时选择 Code：一条设计精良的提示词链、一种不寻常的编排模式、一个带着来之不易的选择器的爬虫、一套别人否则要花一周才能搭起来的工作流。如果价值依赖于你运营的基础设施，或依赖于只有你能触达的数据，那就选别的。

## x402 URL

你提供一个兼容 x402 的 API 端点的 URL。

x402 是面向 API 端点的机器可读目录。当你提供 x402 URL 时，Swarms 会从 facilitator 处发现 API schema，并自动展示集成说明。文档不需要你来写，端点会自我描述，而上架页面把这份描述渲染出来。

当你的智能体是一项由你托管的服务时，这是正确的选择。逻辑保留在你的基础设施上，这意味着你可以在不重新发布的情况下更新它、让专有方法保持私有，并触达买家自己无法访问的数据或模型。代价也是实在的：你的端点必须保持在线，而你的上架页面好不好，取决于你的可用性。

当你在运行一项真实的服务，并希望它能被其他智能体发现和调用，而不只是被人类阅读时，选择 x402。

## MCP URL

你提供一个 MCP 服务器的基础 URL。

MCP，即 Model Context Protocol，是关于智能体如何发现服务并与之交互的新兴标准。当你提供 MCP 服务器 URL 时，Swarms 会连接到它、获取 schema，并使用 MCP 客户端生成 Python 代码示例。买家拿到的是可用的集成代码，而不是关于「集成大概长什么样」的描述。

它与 x402 的区别在于受众。x402 描述的是一个 API 端点；MCP 描述的是一组专为智能体调用而设计的工具，并且协议本身内建了发现机制。如果你做的东西应该能被别人的智能体直接拿去使用，MCP 就是让这件事自动发生的格式。

当你的智能体是提供给其他智能体的一项能力，而不是给人访问的目的地时，选择 MCP。

## Website（网站）

你指向一个 URL。

这是最轻量、也是结构化程度最低的选项。不会获取 schema，不会生成代码，也不会验证任何东西。上架页面只是一个指向别处已有事物的指针。

当你的智能体是一个有自己独立入口的产品、当你想要一个市场展示位和一个代币但不愿暴露 API 接口、或者当你想先把位置占下而稍后再接入真正的实现时，选择 Website。

## GitHub 导入不是第五个选项

表单上方的 GitHub 导入字段经常被误认为是第五种实现类型。它不是，它是一个加速器。

粘贴一个仓库 URL，Swarms 会抓取该仓库并据此预填你的上架信息：名称、描述、主体代码、识别出的语言、建议分类、建议标签，以及作为上架图片的仓库头像。它填入的一切之后都可以编辑。

所以 GitHub 导入是通往 Code 类型上架的快速通道，而不是一种独立的接入方式。它是从现有仓库到已发布智能体最快的路径，而且即便你打算把每个字段都重写一遍，也仍然值得用，因为它帮你处理好了图片和那些样板内容。

## 如何在四者之间选择

| 你的情况 | 接入方式 |
| --- | --- |
| 自包含的代码，希望别人运行和修改 | Code |
| 已经放在 GitHub 上 | 先 GitHub 导入，再走 Code |
| 由你运营的托管 API | x402 URL |
| 供其他智能体调用的能力 | MCP URL |
| 有自己独立网站的产品 | Website |

# 第四部分：提示词

如果你发行的是提示词，就没有实现这一节。你提供提示词内容本身，再加上常规的名称、描述、图片、分类和标签。

这份简单值得被认真对待，而不是被当作次一等的路径。一段能稳定产生特定结果的提示词，对买家来说往往比一个还需要自己接线的智能体更立即可用，而且完全没有维护负担。提示词的代币化条款与智能体完全相同：相同的费率结构、相同的 Frenzy 和 Vault 选项、相同的参赛资格。

如果你手里一直压着一段效果出奇好的系统提示词，那它完全值得作为一次正式发行。

# 第五部分：联合曲线

代币化会为你的上架项目附加一个在 Solana 上实时可交易的代币，而它通过联合曲线实现，不需要你出资建立流动性池。

曲线以算法为代币定价：早期买入更便宜，后续买入价格更高，而你不需要提供任何资本就能起步。

曲线有两个检查点：它以约 3,246 美元的默认初始市值开盘，并在约 46,468 美元时迁移。这两个都是美元目标值。对于以 SOL 计价的池子，它们会按发行时的即时价格换算成 SOL；对于以 USDC 计价的池子，则直接使用。到达迁移检查点意味着代币已经从发行曲线中毕业，这也是大多数项目所瞄准的时刻。

# 第六部分：计价货币，SOL 还是 USDC

每一条联合曲线都以某种资产计价，这就是计价货币，Swarms 支持两种。

**SOL** 是默认选项，也是加密原生的选择。你的代币有 SOL 价格和 SOL 市值，手续费以 SOL 累积，而你的行情图会随 Solana 生态一起波动。

**USDC** 把一切都以美元计价。你的代币有美元价格，市值是一个美元数字，手续费以 USDC 累积。

真正重要的区别在于分母。在以 SOL 计价的曲线上，你的美元市值会随 SOL 波动，这意味着一天里即使你的代币完全没有成交，项目也可能显示上涨百分之十五或下跌百分之十二。在以 USDC 计价的曲线上，这个数字只有在真的有人买入或卖出你的代币时才会变化。噪声消失了，剩下的是关于你项目的干净信号。

由此带来三个实际影响：

- 你的市值衡量的是对你智能体的需求，而不是更广泛市场的状况。
- 不用 SOL 思考的买家看到的是他们本来就理解的价格，这对面向企业而非交易者的智能体尤其重要。
- 手续费以美元到账，因此周一赚到的收入到周五仍是同样的收入。那是收入，而不是风险敞口。

如果你的受众是加密原生、且乐于持有 SOL 的人群，选择 SOL。如果你面向的是想要这个智能体、但完全无意因此顺带持有某条一层网络代币仓位的人群，选择 USDC。

一点关于时机的提醒：计价货币在曲线创建时设定，之后无法更换。请在发行前就决定好。

# 第七部分：Frenzy Mode

Frenzy Mode 是发行时的一个开关，智能体和提示词均可使用，它改变的是你的代币所适用的费率档位。

默认情况下，代币化上架项目每笔交易收取合计 1.0% 的交易费，平均分配：0.5% 给你，0.5% 给平台。Frenzy Mode 会把代币接入一个完全不同的费率档位，把总费率翻倍到 2.0%，其中 1.0% 给你，1.0% 给平台。

| | 标准 | Frenzy Mode |
| --- | --- | --- |
| 每笔交易的总交易费 | 1.0% | 2.0% |
| 你的份额 | 0.5% | 1.0% |
| 平台份额 | 0.5% | 1.0% |

需要准确理解的一点是：Frenzy 并不是把原有的 1.0% 重新分配得对你更有利，而是把每笔交易的成本翻了一倍。你在每单位交易量上赚到两倍，交易者在每笔交易上也要多付一倍。

这是一个真实的取舍，而不是免费的升级。更高的费率就是摩擦，而摩擦会降低换手，对那些被频繁交易的代币尤其如此。当你预期会有可观的交易量、并希望最大化从中获取的收益时，Frenzy Mode 是合理的。如果你的代币很可能交易清淡，那它就不太合适，因为更高的单笔成本可能会抑制掉你原本想从中赚钱的那部分活跃度。

采用 Frenzy 的发行还会出现在 Frenzy 排行榜上，这本身也是一个曝光来源。

# 第八部分：Vault Mode

Vault Mode 把你的代币变成一把访问钥匙。只有持有你智能体代币的人才能使用该智能体。

第一部分已经讲过它如何改变开发者与用户的关系。发行时需要知道的机制要点则更简短。

最重要的结构性一点：**Vault Mode 与定价互斥。**启用 Vault Mode 的上架项目没有购买价格，因为持有代币就是访问机制。你是在「出售访问权」和「以持仓开放访问权」之间做选择，无法在同一个上架项目上兼得。

Vault Mode 适合那些价值在于持续访问、并且你更愿意围绕所有权凝聚社区而不是转化一次性买家的智能体。它不适合任何「直接的一次性购买对买家更有利」的情形，也不适合没人想反复使用的智能体，因为给一个没有持续需求的东西加上访问门槛，等于什么都没有拦住。

# 第九部分：各选项如何组合

这三个开关彼此独立，因而产生了一组有用的组合。

**USDC 加 Frenzy Mode。**以美元计价，搭配翻倍的费率档位。你的收入在每单位交易量上被最大化，且在赚到之后价值稳定。对于预期会有真实换手的项目，这是最偏重收入的配置。

**USDC 加 Vault Mode。**一个以美元定价的访问代币。买家看到的是一个稳定、易懂的访问价格，对于要拿工具去对预算的企业买家而言，这是可读性最强的配置。

**SOL 加 Frenzy Mode。**加密原生、最大化交易量的配置。最适合以 SOL 计价属于默认预期、且能接受较高费率的交易者受众。

**都不开，走 SOL 曲线。**最朴素的默认配置。1.0% 的总费率对交易者摩擦最小，没有访问门槛，也没有美元计价。如果你拿不准，这是一个合理的起点。

三者之中，只有 Vault Mode 会关掉别处的一个选项，因为它排除了设置价格的可能。

# 第十部分：发行流程分步说明

1. 前往 [swarms.world/launch](https://swarms.world/launch)，选择 Agent 或 Prompt。
2. 如果你有仓库，把它粘贴进 GitHub 导入以预填表单。
3. 填写名称、描述、图片、分类和标签。它们决定了是否有人能找到你的上架项目，所以请把它们当作产品的一部分来对待。
4. 对于智能体，选择你的实现方式：Code、x402 URL、MCP URL 或 Website。
5. 对于提示词，提供提示词内容。
6. 决定定价，如果你打算使用 Vault Mode 则跳过这一步。
7. 如果你想附加代币，启用代币化。
8. 选择计价货币，SOL 或 USDC。
9. 设置你的代币代号。
10. 决定是否启用 Frenzy Mode 和 Vault Mode。
11. 发布，然后批准创建代币的钱包交易。

发布和代币化在底层是两个步骤：先创建上架项目，然后在链上铸造代币。如果第二步失败，例如你拒绝了签名请求，上架项目依然存在，你可以稍后从它的页面完成代币化。你不会丢失已完成的工作。

## 常见问题

**发行后可以更换计价货币吗？**不可以。计价货币在曲线创建时被写入联合曲线配置，之后无法更改。请在发布前决定。

**可以之后再加 Vault Mode 吗？**Vault Mode 是发行时的决策，并且与已设置价格互不兼容。请提前规划。

**可以把工具代币化吗？**不可以。工具在任何配置下都不支持代币化。如果你想要代币，请作为智能体或提示词发布。

**提示词的收益真的和智能体一样吗？**是的。费率结构、Frenzy Mode、Vault Mode 以及参赛资格完全相同。

**如果我的端点宕机了会怎样？**对于 x402 和 MCP 类型的上架项目，实现运行在你自己的基础设施上，而一个指向失效端点的上架项目就是一个失效的上架项目。如果你没有把握让服务持续运行，那就改用 Code 发布。

**代币化会妨碍我正常销售吗？**除非使用 Vault Mode，否则代币化的上架项目仍然可以设置价格。代币化是增加一条收入渠道，而不是替换掉原有的那条。

## 更大的图景

值得关心这一切的理由并不是联合曲线的机制本身，而是：一整类工作正在被创造出来，其速度快过了拥有它们所需的结构。

未来会有数以百万计的智能体。它们会完成具有真实经济价值的真实工作。而当下，这些价值几乎全部被托管智能体的平台或其底层的模型提供方所捕获，真正做出这个东西的人拿到的极少。这是一个分配问题，而分配问题的解法，是给人们一种拥有自己所造之物的方式，以及一种让其他人与他们共同拥有其中一部分的方式。

智能体是一项生产性资产。人应当能够拥有一个、能够持有其中的份额，并且能够持续地而非一次性地从中获得收入。这就是全部的论点。

如果你已经做出了能用的东西，那就值得去看看市场认为它值多少。
