# Swarms Cloud 更新日志：8 月 3 日至 9 月 19 日

本文从[上一份更新日志](/zh/blog/swarms-cloud-changelog-july-august)结束的地方继续，覆盖的时间窗口更长也更繁忙：七周、238 次提交，新增的界面比前两份更新日志加起来还要多。

工作的形态再次发生了变化。7 月那段时间主要在让已有页面变得正确，这一段则主要在拓展覆盖面。八个新页面上线，其中好几个是 API 早已支持、控制台却无从驱动的能力：批量运行、批量网格工作流、智能体构建器、加密的提示词库、托管 MCP 服务器页面，以及 S2A 的首批界面。与之并行的还有一条更安静、但比任何单个功能都更重要的主线：一个为瞬时渲染而重建的仪表盘、一套不再可能向你重复收费的计费系统，以及一长串针对"平台自信地告诉你一个错误数字"的修复。

有两点从此前的更新日志延续下来。第一，这里列出的是今天已经在线的东西，因此在这段时间内上线后又被回滚的工作会被略去，除非它以站得住的形式重新落地。第二，凡是已有专门深度解析文章的内容，这里的条目都会写得简短，并给出链接。

## 重点内容

这段时间里最重要的五项。完整的逐日记录紧随其后。

- **[调用日志](https://cloud.swarms.world/history)。** 你的账户发出的每一次 API 请求都可搜索、可筛选，并带有每次运行的 token 用量与成本。每一次调用现在都有自己的页面，承载完整的请求负载与响应，因此单次运行可以被链接、收藏或下载为 JSON。[阅读深度解析](/zh/blog/completion-logs-swarms-cloud)。
- **[每个智能体一个页面](https://cloud.swarms.world/agents)。** 活动与成本、完整的系统提示词、全部 34 个配置字段（你未设置的字段会填入 API 自己的默认值），以及逐次运行查看每次调用实际填满了多少模型上下文窗口。[阅读深度解析](/zh/blog/agent-detail-pages-swarms-cloud)。
- **[S2A](https://cloud.swarms.world/s2a)，beta 版。** 缩容至零的智能体托管。指向一个 GitHub 仓库，在提交之前获得跨云的成本报价，然后部署到最便宜的那一朵云上，背后是一个自动伸缩的 HTTPS 端点，部署记录、模板和日志都在仪表盘里。
- **[Batch](https://cloud.swarms.world/batch) 与 [Grid](https://cloud.swarms.world/grid)。** 让一个智能体跑最多 500 个任务，或者让每个任务与每个智能体组成矩阵逐一运行。两者都会随运行推进逐步填充，带有逐任务进度、仅重试失败项，以及 CSV 导出。
- **[自动智能体构建器](https://cloud.swarms.world/auto-agent-builder)。** 描述一个任务，构建器智能体就会为它设计好整套阵容：包含名称、提示词和模型的完整智能体配置，无需修改即可直接提交给 swarm 端点。

## 8 月 3 日当周

**8 月 3 日**

- **swarm 架构详情页上线**，数据来自 `/v1/swarms/available`，而不是仓库里写死的列表，因此 [cloud.swarms.world/swarms](https://cloud.swarms.world/swarms) 上的 16 种架构描述的是 API 实际提供的内容。这是第二次尝试，第一次在 7 月被回滚。
- 页脚的连接检测现在会在页面加载时执行真实的网络检查，而不是报告一个它并未验证过的状态。

**8 月 5 日**

- 登录和注册页面上那个"You are signing into Swarms"的标签，此前是一个带下拉箭头、点击却毫无反应的禁用按钮，位置就在注册流程的顶部。现在它是纯文本，读起来像上下文说明，而不是一个坏掉的控件。
- 每个架构页面上的快速开始此前会把你引向旧平台去申请 API 密钥。现在它指向 [cloud.swarms.world/api-keys](https://cloud.swarms.world/api-keys)，一次点击即可到达，而不是跳到另一个产品。

**8 月 7 日**

繁忙的一天，三块独立的工作同时落地。

- **[自动智能体构建器](https://cloud.swarms.world/auto-agent-builder)上线。** 描述一个任务，构建器智能体就会为它设计一套可直接运行的智能体配置阵容。每个生成的智能体都会展示它的描述、系统提示词以及构建器设置的每一个参数，支持逐个复制、复制整个数组、复制完整 JSON，或把整套阵容下载为 CSV。你可以限制阵容规模或要求精确数量，选择构建器模型，并传入自定义的构建器指令。
- **[Chat](https://cloud.swarms.world/chat) 上线。** 组建一套阵容，然后和它对话。单个智能体可以直接对话并保有完整的会话记忆，因为每一轮都会通过 completions 的 history 字段提交累积的对话记录。加入更多智能体后，每一轮都会以并发 swarm 的方式运行整套阵容，每个智能体的回复都是带署名的独立气泡，附带它的名称、模型和本轮成本。会话在刷新后依然保留。
- **Token 用量默认打开今天**，而不是当前整月，并且周期标签现在会展开一个交互式日历：两次点击选择区间、悬停预览、今天／最近 7 天／最近 30 天／本月的预设，未来的日期不可选。自定义区间成为与月、周、日并列的一等视图模式。
- **分享链接不再展开成登录卡片。** 爬虫此前被鉴权中间件重定向到 `/login`，因此无论链接指向哪个页面，分享出来的卡片都显示"Log in"。已知爬虫现在会直通公开元数据，并且每个页面都获得了动态生成的社交卡片。

![自动智能体构建器：描述一个任务，构建器智能体就为它设计出整套智能体配置阵容](/auto_agent_builder_banner.png)

**8 月 9 日**

- **可观测性页面被删除，并重定向到 [History](https://cloud.swarms.world/history)。** 它的指标是在客户端从共享日志 hook 的最近 24 小时数据里推导出来的，而不是来自真正的遥测，因此它看起来像监控却并不是监控，这比没有这个页面更糟。页面上所有诚实可信的内容在别处早已覆盖。旧 URL 已被收录和收藏，因此它是永久重定向，而不是 404。
- **swarm 目录支持一键分类筛选。** 每种架构本来就带有分类，但想筛出"负责路由的那些"，得滚动 16 张卡片并逐个读取徽标。现在有一行分类标签可以筛选，能与搜索组合使用，并通过 URL 往返，因此筛选后的视图可以分享。

## 8 月 10 日当周

**8 月 10 日**

- 定价计算器此前接受负数，于是能算出负的价格。输入现已做范围限制。
- 智能体表单此前可能向 API 发送为零或为负的 `max_loops` 或 `max_tokens`，这会先收取每个智能体的费用，然后什么都不运行。两者现在都有下限。
- **模型列表告别了 GPT-4o 时代。** 驱动静态页面、站点地图和推荐排序的那 20 个模型 id 被替换为一组当前的、覆盖多家供应商的集合，涵盖 Anthropic、OpenAI、Google、xAI、DeepSeek、Meta 和 Moonshot，每个 id 都对照当时 1,605 个模型的实时目录做过核验。可运行的示例代码刻意只使用经过端到端验证可用的模型。
- 执行记录和已保存工作流的"最近"排序做了 NaN 安全处理。

**8 月 12 日**

计费，尤其是使用钱包登录的账户。

- **套餐选择加入了新手引导流程。** 创建第一把 API 密钥之后，你会看到 Free、Pro 和 Premium 的选择器，而不是事后才发现有这些套餐。
- 钱包账户在结账后无法同步自己的套餐层级，因为同步路径要求有一个已确认的邮箱来匹配 Stripe 客户。现在它按每个订阅上标记的账户 id 匹配，邮箱作为回退方案。
- 钱包账户注册时没有名称也没有邮箱，而且无从补充。设置页现在提供了两者的编辑表单。
- 结账失败此前只返回一个笼统的 500。Stripe 的权限错误、过期密钥和缺失价格现在会映射为明确的响应，并指出该如何解决。
- 钱包登录携带的是空字符串邮箱，而 Stripe 会拒绝它，因此**每一次钱包账户的升级都在失败**。当没有真实邮箱地址时，该字段现在会被省略。

**8 月 13 日**

两项数据安全修复。

- **已保存的工作流和已保存的智能体配置在退出登录时没有被清除。** 两者都会持久化到浏览器，也都携带系统提示词、任务文本和存下来的运行输出。在共用的浏览器上，下一个登录的账户可以打开工作流构建器，读到上一位用户的工作成果。现在每一个持久化存储要么在退出登录时清除，要么是有明确记录的、仅存偏好设置的例外。
- **结账可能让你付两份钱。** 此前没有任何环节检查你是否已经有订阅，而设置页里的"切换套餐"按钮调用的是同一个端点，于是一次套餐切换会开出第二个并存的订阅。所有读取路径都只取最新的那一个，因此设置页显示一个套餐、取消按钮也只作用于一个订阅：取消它之后，较早的那个订阅仍在扣费，而你的层级却掉回了免费。第二次结账现在会被拒绝。

**8 月 14 日**

- **CSV 导出的一项安全修复。** 电子表格会把以特定字符开头的单元格当作公式执行，而导出的列里含有调用方可控的文本，比如任务和智能体名称，因此一个导出文件可能在打开它的人的机器上执行点什么。现在每一次导出都经由同一个加固过的写入器。数字例外的判定也收紧了：旧的检查会放过 `+1e5`，Excel 会对它求值并改写为 100000，同时又会中和 `-1,234.56`，导致该列的求和失效。
- **一个用户的模型目录可能被提供给另一个用户。** `/api/models` 有鉴权保护，并且使用登录用户自己的密钥去请求，但它的缓存头写的是 `public`，这等于授权共享缓存和 CDN 存下这个响应，并在十个小时内回放给任何人，而请求根本不会到达那个本该拒绝它的处理器。现已标记为 private。`/api` 下的其他每一个路由都做了排查，这是唯一一个。
- **吊销一把 API 密钥会抹掉它的历史支出。** Token 用量按仍然有效的密钥来过滤日志查询，因此轮换凭证这件 API 密钥页面本身在鼓励的事，会让这把旧密钥支付过的每一次调用从图表、表格、导出和成本合计里消失。没有报错，没有警告，只是一个你无法和账单对上的更小的数字。

**8 月 15 日**

- Compare 页面开放了推理与采样参数，它的数字输入框也做了范围限制。

**8 月 16 日**

- **套餐切换现在可以正常工作了。** 8 月 13 日的修复通过拒绝第二次结账并提示你先取消，止住了重复计费。这次则把"拒绝"换成了真正的切换：升级立即生效并按比例结算，未使用的时间会被抵扣，只收取差价，扣款失败会干净地中止。降级则让你保留已付费的套餐直到当前周期结束。选择套餐同时会清除待生效的取消操作，而在降级待生效期间重新选择当前套餐，会取消这次降级。
- 一次依赖与死代码清理移除了六个无引用文件和两个根本跑不起来的包。
- 聊天记录现在也会在退出登录时清除，与 13 日修复的那些存储一起。

## 8 月 17 日当周

这段时间里最密集的一天。

**8 月 17 日**

- **仪表盘的鉴权环节快了大约八倍。** 此前每一个 API 路由的每一次请求，在能够触及缓存之前都要跑两次数据库往返，其中五个路由还要跑第三次，只为拼出自己的缓存键，而轮询会永远重复支付这份开销。现在每次加载大约是 2 次往返，而不是 17 次。
- **而且刷新后可以瞬时渲染。** 刷新会清空内存缓存，于是仪表盘的五个请求全部重发，页面闪过一片骨架屏，尽管服务端会返回一模一样的字节。响应负载现在按用户持久化在浏览器里，并标记写入它的账户，一旦不匹配就丢弃，因此刷新会先用最近一次的状态渲染，再在背后悄悄重新校验。
- **[批量运行](https://cloud.swarms.world/batch)上线。** 让一份智能体配置跑最多 500 个任务，任务可以粘贴、以 CSV 上传，或以 JSON 提供。带 ETA 的逐任务进度、只重试失败项、筛选结果，运行途中刷新也不会中断。
- **你的套餐层级不再自相矛盾。** 决定 API 功能权限的层级在上游，而平台自己的表只跟踪 Stripe 套餐，两者可能不一致。设置页和付费功能的权限判断现在都读取上游层级，因为决定你的调用能否成功的正是它。
- **订阅状态现在是可见的。** 每个层级显示旁边的标签会展示续费日期、结束日期或扣款问题。逾期的订阅此前是不可见的，因为层级会静默重置为免费，而生效中的横幅会隐藏。
- **付费端点现在会解释自己。** 由订阅专属端点支撑的页面会打开一个以该功能命名的套餐选择器，而不是让你先搭建一通，再从一个 403 里发现限制。
- 所有升级引导按钮此前仍然指向旧平台的账户页面，那是在本平台拥有自己的计费系统之前写的。现在它们指向一次点击即可到达的结账页。
- 站点地图现在由应用目录生成，而不是一份早已漂移的手工维护列表，并且 **[llms.txt](https://cloud.swarms.world/llms.txt) 已生成并对外提供**，包含实时定价、每一个公开页面和每一种 swarm 架构。
- 设置页现在显示来自你 OAuth 身份的真实姓名和头像，而不是首字母缩写和一个邮箱地址。

**8 月 18 日**

- **[Skills](https://cloud.swarms.world/skills) 上线：一个私密、加密的提示词与技能库。** 支持一次上传多个文件，格式可以是 Anthropic 的 SKILL.md、纯 markdown 或 JSON。可按名称、描述、标签和内容搜索。每个技能都有自己的页面，支持就地编辑。所有内容在静态存储时都使用按用户派生的密钥加密，因此错误用户的密钥无法通过认证，归属权由密码学和查询条件共同保障。
- 批量分块的大小改为 API 实际执行的上限，而不是它的规格文档宣称的那个。

![加密 Skills 库中的一个技能页面，带有统计条、渲染预览，以及"私密且加密"的标识](/swarms_cloud_skills_library.png)

**8 月 19 日**

- Skills 增加了统计条，展示字符数、词数和 token 数，还有安全的 markdown 渲染预览以及复制副本的操作。
- **仪表盘增加了"快速开始"板块**，代码片段生成器增加了 Rust。
- **[Support](https://cloud.swarms.world/support) 上线**，把各个联系渠道集中到一处。
- **浏览器存储配额耗尽不再让 Chat 崩溃。** 页面此前在每条消息上都会无保护地写入整段会话，因此一旦该源的存储写满，之后每条消息都会失败，并且在刷新后依然坏着，直到你手动清除站点数据。现在它会分级降级，优先保留你手工组建的阵容而不是对话记录，并在不得不这样做时提示你一次。

**8 月 20 日**

- 日志调用从一个已弃用的别名迁移到 `/v1/account/logs`。同一个调用同时支撑 History 和仪表盘的活动卡片，因此别名一旦消失会同时打掉两者。
- **工作流构建器在运行前就能发现环，而不是运行之后。** 此前带环的图能通过校验，运行按钮保持可用，请求照常发出。处在环里的智能体永远不会出现在拓扑分层中，因此它们干脆从未运行：一个顺利完成的请求，悄悄缺失了环里的一切。

**8 月 21 日**

- 批量分块提升到 50，因为端点现在接受 50。一次 500 任务的运行只需 10 次往返，而不是 50 次。
- API 密钥创建限制为每个账户 100 把有效密钥。此前完全没有上限，因此针对一个会话的循环可以无限制地生成可用凭证，而每一把都需要单独吊销。

**8 月 22 日**

- **History 的 CSV 导出少算了费用。** 它只读取费用可能出现的三个字段中的一个，因此图工作流、网格工作流、自动智能体构建器和 swarm 运行的成本列是空的。你带走用来对账的那份文件，恰恰是算错的那个。
- `/models/<任意字符串>` 会为任何字符串返回一份完整的、看起来很正式的模型说明页，连结构化数据和可复制粘贴的请求负载都有，而那个字符串就被当作模型 id。不对应任何模型的 id 现在返回 404。
- token 费率此前在六个地方手工写死，其中五处在正文里。它们当时是一致的，但没有任何机制保证它们继续一致。现在只有一份定义，其余全部由它推导。

**8 月 23 日**

- 修复了 CI，让三套 API 测试真正运行，并且 fork 场景下的跳过是可见的，而不是藏在一个绿色对勾里。
- 含逗号的技能标签此前会被静默存成两个标签，这意味着一次导入可能加上你从未写过的标签，同时丢掉一个你写了的。

## 8 月 24 日当周

**8 月 24 日**

- **[MCP 页面](https://cloud.swarms.world/mcp)上线**，面向托管的 Model Context Protocol 服务器：端点、实时状态、连接代码片段和教程。状态来自服务端发出的真实 MCP 握手，而不是一次 ping，因为一个裸请求只能证明主机在监听。可用性被如实报告为"N 次检查中的观测结果"，而不是包装成 SLA。
- **工具清单从服务器读取**，而不是写死在代码里，因此 API 新增一个工具，这里就会出现，页面无需改动。它支持以画廊或表格呈现。

![MCP 页面：托管的 Model Context Protocol 端点、实时状态、连接代码片段与工具清单](/mcp_page.png)

**8 月 25 日**

- **定价从 API 读取公布的费率表。** 控制台此前使用仓库里的一份副本报价，而 API 提供的才是真实的那份，因此上游的费率变更在这里是看不见的，直到有人编辑这个仓库并重新部署。格式异常的负载会被拒绝而不是渲染出来，因为在客户据以了解价格的页面上显示 $0.00，比显示一个过期价格更糟。
- **十二条问答的 FAQ 加入了 Support**，位置在联系渠道之上，让自助排在前面。套餐名称、价格和注册赠额都从各自的数据源插值而来，而不是重新手打一遍，因此这份 FAQ 不会过期。

**8 月 26 日**

- MCP 工具目录支持搜索。这些名称由机器生成，长达 64 个字符，并且把有意义的部分埋在中间，因此一份没有筛选的参考列表意味着为了回答一个问题要读完全部 23 个。

**8 月 27 日**

又是非常繁忙的一天。

- **[Examples](https://cloud.swarms.world/examples) 上线：** 一个可浏览的示例库，涵盖 agents、swarms、batch 和 account 的可直接运行的 API 调用，每一条都能展开成可复制的代码片段，覆盖我们支持的每一种语言。在此之前，想知道一条顺序流水线长什么样，唯一的办法是去读 OpenAPI 规格。
- **[Grid](https://cloud.swarms.world/grid) 上线：** 批量网格工作流的运行器。一份任务列表、一份智能体列表，以及一个任务为行、智能体为列的结果矩阵。在此之前，把 M 个任务跑在 N 个智能体上的唯一方式是直接调用 API。
- **全平台语法高亮。** 平台上的每个代码块此前都渲染成单一颜色，而 markdown 渲染器会丢掉模型输出里的语言标注，把每个代码块一律涂成绿色，无论它是 Python、JSON 还是 shell 命令。现在每一处代码界面都使用与 VS Code 相同的引擎和语法定义、在 VS Code 的配色上高亮，因此这里的代码片段看起来和在编辑器里一样。两次后续提交把它挡在了每个页面的首次加载之外，因此从不展示代码的页面不必为它付出代价。
- **生成的 Python 与 TypeScript 代码片段有了真正的类型标注。** 两者此前都不带类型，而那是没人会手写出来的代码形态。这同时修掉了一个真实缺陷：Python 片段此前把布尔值渲染为 `true` 和 `false`，因此任何带布尔值的负载生成出来的片段，粘贴后都会直接报错。

![Examples 示例库：涵盖 agents、swarms、batch 和 account 的可直接运行 API 调用，每一条都能展开成可复制的代码片段](/api_example_suite.png)

**8 月 28 日**

- **一份智能体定义，一个编辑器。** 三个页面各自携带一份手写的 API 智能体对象副本，字段数分别是 18、12 和 19，而 API 实际接受 34 个。其中两份还定义了 API 根本没有的字段。于是同一个智能体会因为你打开的页面不同而被配置成不同的样子，而 API 接受的大部分能力在任何地方都够不着：Grid 的编辑器只开放了 34 个字段里的 3 个。现在只有一份定义，由测试对照已发布的规格校验，并且有一个覆盖全部字段的编辑器。
- Grid 和 Examples 被登记进应用目录，它们上线时漏掉了这一步，因此两者都没出现在应用目录、导航搜索、站点地图和 llms.txt 里。导航栏另存了一份同样的列表，这正是问题得以发生的原因，现在它由目录推导而来。
- **Skills 支持导入文件夹**，因为技能实际上就是这样分发的：每个技能一个目录，里面放一个 SKILL.md。此前拖入一个目录什么都不会导入。一批文件中有一个有问题，也不再导致整次导入失败。
- Grid 矩阵在运行之前就会渲染，而不是只在运行之后，因此页面会先展示它即将产出的形状，而不是 400 像素的空白。

**8 月 29 日**

- **[每个智能体一个页面](https://cloud.swarms.world/agents)上线**，包含活动记录、完整的系统提示词、全部 34 个配置字段（你未设置的字段带有 API 自己的默认值），以及逐次运行查看每次运行实际填满了多少模型上下文窗口。它有自己的[深度解析](/zh/blog/agent-detail-pages-swarms-cloud)。
- **Examples 现在会带着完整负载在 playground 中打开。** 此前那个链接只传递 swarm 类型，于是你到达的是一个默认的空表单，示例本身想要演示的一切都在路上被丢掉了。
- **定价页变成了一张对比表。** 旧页面完全没有说明订阅究竟买到了什么，因此想知道图工作流、批量运行、推理智能体和 Grid 是订阅专属的，唯一办法是调用一次然后读那个 403。现在的首行直说了旧页面埋起来的事实：所有套餐在所有模型上支付相同的单位 token 价格，因此订阅买到的是访问权限和吞吐能力，而不是更便宜的 token。计算器搬到了自己的页面。

## 8 月 31 日当周

一段以正确性为主的工作，其中大部分发生在那些悄悄报告了错误内容的地方。

**9 月 1 日**

- 两个页面上的工作流级循环次数使用的解析表达式，一个会放过负值，另一个会放过小数，而这两个值都会直接进入请求。现在两者都使用其余十二处调用早已在用的同一个守卫。
- **"60 分钟前"和"24 小时前"不会再出现。** 每个相对时间分支都是按阈值进入、再四舍五入到最近的整数，因此每个单位的最后三分之一都会被报告成下一个单位的完整值，而 36 小时在只过了一天时被读成"2 天前"。
- 在智能体页面上更换模型后，页面仍然显示上一个模型的上下文窗口，而且是以一个已确定的数值呈现，而不是加载中的状态。
- **批量运行中被跳过的一个任务，会让它之后的每一条结果对错行。** 路由会把不可用的任务过滤掉再运行剩下的，而页面按位置把答案映射回去，于是第 1 行装着第 2 行的答案，最后一行则对一项已经运行并已计费的工作报告"无结果"。现在这样的批量会被拒绝，并指明出问题的索引。

**9 月 3 日**

- **Grid 结果矩阵扛得住 50 个智能体了。** 此前表头行会滚走，于是一个很宽的网格变成一面没有名字的答案墙，任务列也会横向滚走，而点击单元格打开的面板位于一张 24 行任务表之下，远在首屏之外。现在矩阵在自己的区域内滚动，表头和任务列固定，单元格详情以侧边抽屉打开。
- 推理强度选择器在值未设置时显示"low"，因此打开推理却不去动强度，提交的请求里根本没有设置强度，而页面却显示有。

**9 月 4 日**

- 社交卡片现在使用站点自己的深色配色，而不是一套不相干的浅色配色。
- Grid 的循环次数字段像页面上其他限制一样展示自己的上限，并说明一次循环的代价：每一次都是一次计费的调用。

**9 月 5 日**

- **生成的提示词可以直接保存进你的 Skills 库。** 提示词生成器此前只提供复制，别无他选，于是输出都流进了本地笔记。

**9 月 6 日**

- Chat 的阵容侧栏改用共享的智能体编辑器。Chat 此前定义了自己的三字段智能体类型，因此它提交的 swarm 永远无法携带 temperature、回退模型、MCP 服务器或工具。

## 9 月 7 日当周

**9 月 7 日**

- **导航栏变大了**，搜索框、Docs 和 Status 按钮也相应调整了尺寸。
- **吸顶导航栏真的吸顶了。** 用 `overflow-x: hidden` 阻止横向滚动，会把 body 变成它自己的滚动容器，于是头部相对于一个永远不滚动的盒子计算偏移量，结果就跟着页面一起滚走了。
- 退出登录现在会清除按用户划分的内存缓存，而不只是浏览器存储。登录和退出都以软导航结束，因此模块状态的寿命超过了填充它的那个会话。

**9 月 8 日**

- **Grid 会随运行推进逐步填充。** 此前一次运行是针对整个矩阵的单个阻塞请求，因此一个 50 乘 50 的网格，也就是 2,500 次调用，在整个等待期间只有一个按钮上的一个加载图标。现在每一行完成就落地，每个单元格携带自己的状态，用量也随之累加。调用次数不变，成本不变。

**9 月 9 日**

- **五个官方入门技能**，一键即可加入你的库：swarm 架构选择器、提示词精简器、成本感知的模型选择器、评估标准撰写器，以及智能体故障排查包。
- **Token 用量会根据当前周期已花费的金额预测月末支出**，并且宁可不回答也不乱回答：周期进度不足百分之十时，一次早期运行会推出一个荒谬的月度数字。卡片会显示它据以外推的时间进度比例。

- 在未配置 Supabase 时，本地开发会遵循 `SWARMS_API_KEY`，这是 README 一直承诺、而代码并未做到的事。

**9 月 11 日**

- 来自 Outlook、Hotmail、Live 和 MSN 地址的注册被拦截，密码和魔法链接两条路径都拦，并且不再发放免费额度。

## 这段时间的总账

八个新页面：自动智能体构建器、Chat、Batch、Skills、MCP、Examples、Grid、Support，加上 S2A 及其部署界面，再加上每个智能体一个页面和每次调用一个页面。

在这之下，还有一条值得点名的主线。上面相当大一部分修复属于同一类 bug：平台显示了一个并不真实的数字或状态。一个与实际管控你调用的层级并不一致的套餐层级。四类端点的成本列一片空白。轮换密钥后凭空消失的历史支出。属于上一个模型的上下文窗口。装着下一行答案的批量结果行。显示了却从未被发送的推理强度。这些都不会抛出错误，而这恰恰是它们值得追查的原因：一个被自信地呈现出来的错误数字，比一次失败更难被发现。

另一条主线是收敛。一份智能体定义，而不是三份。一份成本映射，而不是每个使用方各自一份。一份费率表，从 API 读取。一个编辑器、一套代码块外框、一份导航列表。它们中的大多数，最初都是某一份副本里的一个 bug。
