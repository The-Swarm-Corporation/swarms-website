# Swarms Cloud 更新日志：7 月 14 日至 8 月 3 日

本文从[上一份更新日志](/blog/swarms-cloud-changelog)结束的地方继续。格式不变：按实际上线的顺序，逐周、逐日梳理发生了什么，并说明每项改动对你意味着什么，而不仅仅是内部发生了什么变化。

三周比上一份日志覆盖的时间窗口更短，工作的形态也不一样。之前的两个月主要在增加新的界面：新页面、新筛选、新导出。这三周则主要在让已有的东西变得正确、值得信赖：会话不再莫名失效，swarm 元数据与 API 保持一致而不是逐渐漂移，一次附带公开披露政策的安全加固，以及一个无需账户即可查看的定价页面。

正式开始之前先说两点，都是从上次延续下来的。第一，这份日志只列出今天已经在生产环境中生效的工作。有几项改动在这段时间里上线后又被回滚，由于它们从未以可用的状态到达你手中，这里将其略去：7 月 15 日在 Token 用量页面上两次尝试的日历控件、7 月 24 日 swarm 架构页面的第一版，以及 8 月 2 日一项让首屏渲染变慢而非变快、当天即被撤回的仪表盘性能改动。凡是回滚后又以新形式落地的工作，下面记录的都是你实际可以使用的版本。第二，工作流构建器已有专门的[深度解析文章](/blog/workflow-builder-swarms-cloud)，因此它在这里的条目会刻意写得简短。

## 7 月 13 日当周

**7 月 14 日**

- 智能体表格围绕你实际会浏览的信息做了重组。移除了总完成次数列，加入了行序号，并把描述列移到名称列旁边，让识别一个智能体所需的两项信息并排出现。排序选项也同步收紧，移除了 `updated_at`，因为它和创建时间提供的信息是重复的。
- API 密钥页面现在支持分页。如果你积累的密钥超过一屏，它们不再以一个长列表的形式渲染。
- 智能体页面上的创建智能体按钮现在指向 [Workbench](https://cloud.swarms.world/workbench)，而不是仪表盘首页，按钮会把你带到你按下它想去的地方。

**7 月 15 日**

- Token 用量页面围绕明确的起止日期重建，不再按固定的周和月周期逐步切换。你选定想看的精确时间窗口，这个窗口会被原样传给 API，因此图表、时间分桶和总计描述的都是同一个范围，而不是图表显示一个周期、总计却汇总另一个周期。日分桶根据你选择的范围生成，也就是说选三天的范围就渲染三列，而不是补齐成一整周。

**7 月 16 日**

- 修复了全新账户的首次使用报错。当账户还没有额度记录时，额度接口会返回 404，这对一个刚创建几秒的账户来说是正常情况，但平台却把它当作失败来展示。缺失记录现在被视为零余额，新账户会渲染一个干净的空状态而不是错误提示，额度 hook 也不再把一条缺失记录变成每三十秒重复一次的控制台报错。

**7 月 17 日**

- 加入了持续集成。现在每次推送和每个拉取请求在合并之前都会运行类型检查、代码检查和测试套件。这项工作从外部完全不可见，而这正是它的意义：它是防止这份清单里其余改动出现回退的机制。

**7 月 19 日**

- 对主要页面做了一轮文案梳理，移除面向用户文本中的破折号，保持语言风格一致。

## 7 月 20 日当周

**7 月 20 日**

- **已保存流程（Saved Flows）在[工作流构建器](https://cloud.swarms.world/workflow-builder)上线。** 你现在可以为搭建好的图命名并保存，查看已保存流程的列表，把某一个重新加载回画布，并删除不再需要的流程。在此之前，一个工作流的寿命和浏览器标签页一样长。已保存的流程持久化在你的浏览器中，因此可以在刷新后保留，但暂时还不能跨设备同步。

**7 月 21 日**

- 一轮后续文案清理，完成了 19 日开始的破折号移除工作。

## 7 月 27 日当周

**7 月 27 日**

这一天是安全日，四项相关改动同时上线。

- **修复了执行输出渲染中的一个跨站脚本（XSS）漏洞。** 智能体的输出以 markdown 渲染，而代码块在插入页面时没有做转义。如果模型在围栏代码块里返回 HTML，那段 HTML 就可能在你的浏览器中被执行。代码块现在会被转义，转义范围也扩大到引号字符和尖括号。
- **Markdown 链接现在会做协议校验。** 只有 `http`、`https`、`mailto` 和相对链接会渲染为可点击的链接。其他一切，包括 `javascript:` URL，都会渲染为纯文本。由于智能体输出常常是来自模型的不可信文本，这两项修复在这里比在普通内容页面上重要得多。
- **Stripe 客户匹配现在要求邮箱已确认。** 之前用未确认的邮箱地址匹配计费账户，意味着一个未经验证的地址可以被用来关联到某个 Stripe 客户。账单历史和账单同步两条路由现在都要求 `email_confirmed_at` 之后才进行匹配，错误信息也会明确说明这一点。
- **发布了安全政策和一份完整审计。** [SECURITY.md](https://github.com/The-Swarm-Corporation/swarms-cloud-platform/blob/main/SECURITY.md) 说明了如何报告漏洞，以及报告之后会发生什么。一份配套的审计文档记录了对整个代码库审查的发现，包括上面修复的两个问题。同时启用了每周运行的 Dependabot，依赖更新会以可审阅的拉取请求形式到达，而不是无声地积压。

**7 月 30 日**

- **修复了让你在两次访问之间被登出的 bug。** Supabase 的刷新令牌每次使用后都会轮换，旧令牌随即作废。而一次页面加载会同时发起多个 API 请求，每个请求都在独立地尝试兑换同一个刷新令牌。一个成功，其余的收到"已被使用"的错误，会话随之被清空。这就是为什么即使 cookie 本身还有几个月有效期，会话也撑不过一次回访。令牌刷新现在收拢到一处统一处理，登录跳转上一个会清空会话的边界情况也一并修复。
- **[定价页面](https://cloud.swarms.world/pricing)现在公开可见。** 它不再需要账户，你可以在注册之前就了解平台的价格。页面同时列出了订阅档位，Pro 为每月 $19.99，Premium 为每月 $99.99，价格直接从计费实际扣款所用的同一份套餐目录渲染，因此页面上标示的价格不可能与实际收取的价格出现偏差。原有的 token 成本计算器保持不变，位于档位下方。
- **退出登录不再让你在所有设备上同时退出。** 之前退出登录使用的是全局范围，会吊销账户下的每一个会话，在笔记本上退出也会结束你手机上的会话。现在它只作用于你当前使用的设备，这也是菜单项一直以来所声称的行为。

**8 月 1 日**

- swarm 架构元数据现在从实时的 `/v1/swarms/available` 接口渲染，而不是一份手工维护的本地目录。一个每逢 API 变化就要手动更新的六百行本地文件被删掉了。实际效果是：应用里列出的架构，就是 API 真正支持的架构，永远如此。同一项改动还从 swarm 类型列表中移除了 `AutoSwarmBuilder`，因为它并不是一个有效的 `swarm_type`，选中它会构造出一个必然被 API 拒绝的请求。

**8 月 2 日**

- **在页脚加入了连接检测和区域视图。** 连接控件会验证你的设备能否真正连上 Swarms Cloud，并报告往返延迟。检测通过时它有意不显示错误，而是告诉你连接正常，并把你指向服务状态页面，因为当你自己的网络健康时，这是唯一有用的下一步。它区分三种情况：你的设备离线；你的设备在线但连不上我们，这通常意味着 VPN、代理或防火墙；以及一切正常。旁边的区域菜单列出了 Swarms Cloud 运行的四个区域：美国西部、美国东部、欧洲西部和东南亚。

## 8 月 3 日当周

**8 月 3 日**

- **swarm 架构详情页上线。** 每种架构现在都有自己的页面，位于 `/swarms/<type>`，内容基于实时 API 而非静态列表构建，涵盖这种架构做什么、什么时候该用它。与 8 月 1 日的改动结合起来，目录页和详情页现在读取的是同一个数据源，API 更新时它们会自动跟随更新。
- 页脚的连接检测现在会在页面加载时自动运行，而不是等你点击，因此页脚始终反映你真实的连接状态。它每次页面加载只运行一次，而不是每次导航都运行；如果你掉线后重新联网，它会自行重新校验，而不是停留在过期状态。

## 结语

这三周的主题是正确性优先于界面数量。这里几乎没有新增的可点击入口。会话修复消除了一个在两次访问之间悄悄把人登出的 bug，这类问题会侵蚀用户对平台上其他一切的信任。安全日堵住了两个真实的漏洞，并发布了说明如何报告下一个漏洞的政策。把 swarm 元数据迁移到实时 API 消除了一整类漂移问题：应用声称支持某种能力，而后端实际上并不支持。额度修复则消除了每一个新账户在注册后几秒内必然遇到的报错。

那些回滚值得写出来，而不是藏起来。这段时间里有三项工作上线后又被撤回，其中包括一项仪表盘性能改动：它减少了服务器的总工作量，却让页面感觉更慢了，因为它让每张卡片都等待最慢的那个请求，而不是各自就绪各自呈现。上线、测量、当天回滚，这是流程在正常运转，而不是流程失灵。三项之中已有两项以站得住的形式重新落地，第三项仍在审阅中。

如果你想深入了解本文提到的几个较大系统，可以阅读[深入 Swarms Cloud 工作流构建器](/blog/workflow-builder-swarms-cloud)了解如何可视化搭建多智能体图，或阅读[全新 Swarms Cloud 更新](/blog/all-new-swarms-cloud-updates)了解 Token 用量仪表盘和模型目录。
